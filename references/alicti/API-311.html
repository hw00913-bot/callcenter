新增任务接口

  • 接口说明

    接口支持创建预测外呼和自动外呼任务，任务类型通过type字段区分。

    创建任务数如果超过最大任务限制，接口提供参数自动删除最早已完成的任务。

限制说明

为确保平台服务稳定性，本API设定以下使用限制：

  1. 企业级限制
    • 可创建任务数：≤ 100 个
    • 可导入号码数：≤ 1000 万个
  2. 超额处理
    当触发上述任一限制时，本次请求失败。
  3. 最佳实践建议
    • 新增任务接口提供参数自动删除最早已完成的任务： autoDelete: 创建任务超出最大任务数限制时，是否自动删除已完成的最早创建的任务，值为1代表自动删除
    • 平台提供删除任务接口「删除任务」：业务平台可根据实际情况定期自动删除已完成的任务

说明：删除任务时任务内的号码清单会全量删除，平台已呼叫过的通话记录明细、录音文件会继续保留

暂停任务超时自动结束说明

平台会定期扫描处于「暂停」状态的任务，若连续暂停时长超过阈值，系统将自动结束该任务（结束原因：系统自动结束）。任务进入结束状态后无法再次启动。

  1. 默认规则
    • 默认阈值：连续暂停 30 天（以任务暂停时间为起点计算）
    • 未配置企业级开关时，按上述系统默认阈值执行
  2. 企业配置（predictive_task_pause_auto_stop，需联系管理员配置）
    • value=0 或未配置：使用系统默认阈值（30天）
    • value=1：使用企业自定义阈值，超时天数配置在 property（正整数，单位：天；例如 property=15 表示连续暂停超过15天自动结束）
    • value=2：跳过，该企业不执行暂停任务超时自动结束
  3. 说明
    • 该能力为平台侧后台处理，非本接口入参；任务创建后若长期处于暂停状态（例如 autoComplete=0 号码呼完后自动暂停、人工暂停等），可能触发自动结束
    • property 仅在 value=1 时生效；property 非法或小于等于0时，仍按系统默认阈值执行

接口定义

  • API URL
    接口请求地址：
    https://api-{region}.alicti.cn/interface/{version}/task/create
    地址参数说明：
    {region}为alicti平台区域，{region}=1 表示华东1区，{region}=2 表示华北2区，{region}=5 表示华东5区，{region}=6 表示华北6区
    {version}为接口版本，当前{version}=v10
    接口请求方式：
    GET/POST请求

validateType=1时，MD5({departmentId}+{timestamp}+{部门token值})；

  • 优先级和重试策略
参数 类型 要求 描述 备注
retryStrategy String 可选 重试策略 「基础模式」
数据结构为Json格式{"retry":2,"strategy":[{"round":1,"time":"1-1-1"},{"round":2,"time":"2-2-2"}]}
格式说明：retry是重试次数，round是第几次重试，time是第几次重试间隔的时间：1-1-1，第一个1是天，第二个1是小时，第三个1是分钟
「高级模式」
高级模式需要开启「号码状态识别」服务
数据结构为JsonArray格式 [{"condition":{"sipCause":[710,719]},"retry":1,"sort":1,"strategy":[{"round":1,"time":"0-0-10"}]},{"condition":{"sipCause":[800]},"retry":1,"sort":2,"strategy":[{"round":2,"time":"0-0-10"}]}]
格式说明：condition是重试条件，sort是重试条件的顺序，其余字段与基础模式一致

注：基础模式和高级模式的区分根据传入的参数格式自动识别。基于首次呼叫时间重试时，每轮的重试时间必须大于上一轮的时间
retryStrategyTimeType Int 可选 重试策略时间类型 配置重试策略时生效。 1.基于首次呼叫时间 2.基于上次呼叫时间，默认基于首次呼叫时间
retryStrategyOnlyToday Int 可选 任务仅当天生效 0.关闭 1.开启，删除待重试的数据和待呼叫的数据 2.开启，删除待重试的数据 3.开启，删除待呼叫的数据，默认关闭
callPriorityStrategy String 可选 呼叫顺序 数据结构为Json格式{"strategy":[{"sort":1,"type":"retryCall", "desc":0},{"sort":2,"type":"firstCall","orderType":0}]}
格式说明：sort是重试号码和未呼叫号码的呼叫顺序
type：retryCall重试号码、firstCall未呼叫号码
当type=retryCall，desc：0.优先呼叫待重呼轮次数值较小的号码，即轮次靠前（如第1轮、第2轮）的号码先被呼叫 1.优先呼叫待重呼轮次数值较大的号码，即轮次靠后（如第5轮、第4轮）的号码先被呼叫
当type=firstCall时，orderType：随机呼叫，0顺序(优先级) 1随机 2顺序(导入时间)

座席当日接听数限制说明
功能概述：  
    座席当日接听数限制功能用于控制座席在一天内的最大接听数量，确保座席工作负荷合理分配，提升服务质量。
座席当日接听数限制生效条件：  
    座席当日接听数限制功能需要联系管理员开启配置，开启后系统才开始统计当日接听数。
座席当日接听数限制机制：  
    双重限制-支持企业级别和单任务级别双重限制。企业级别限制作用：作为全局兜底限制，防止座席过度工作。单任务级别限制作用：针对具体任务进行精细化控制。
    优先级控制-取两者中的较小值作为最终限制。最终限制数 = MIN(企业级别配置, 单任务级别配置)
        示例：
            - 企业级别座席接听数限制: 10次/天
            - 任务中座席接听数限制: 5次/天
            - 最终限制: 5次/天（取较小值）
    灵活配置-可根据不同业务场景进行精细化控制
配置建议  
    1. 企业级别配置
        考虑因素:
            - 座席工作经验
            - 平均通话时长
            - 工作强度要求
        作用: 作为全局兜底，防止座席过度工作
    2. 单任务级别配置
        考虑因素:
            - 任务复杂度
            - 客户重要性
            - 座席专业能力
        作用: 针对具体任务进行精细化控制
    3. 配置策略
        企业级别 > 单任务级别
            - 企业级别: 配置较大值，作为全局兜底。用于限制多个任务接听总数
            - 单任务级别: 配置较小值，进行精细控制。用于限制单任务接听数
