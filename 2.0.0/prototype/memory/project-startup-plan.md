## 产品形态
面向运营、电话坐席、租户管理员、超管及有权专业资源/财务人员的桌面 B 端演示原型。名称为 D联络云；载体为普通本地 HTML/CSS/JavaScript，唯一交付入口是本目录 index.html。演示系统不连接真实认证、CTI、供应商、计费或客户系统。

## 项目目的
让使用者清楚区分业务如何管理、客户如何维护、呼叫能力如何配置。按已确认的六入口组织现有能力，复用原 AI 卡片、筛选、标签、弹窗和原云呼叫表单、列表、电话条及报表。评审可操作的原流程及本方整合规则，不把原型当生产闭环证明。

## 项目范围

## 核心流程
1. 统一演示登录→单租户直达/多租户选择或恢复合法租户→按原默认意图进入有权业务页。没有统一首页；后续恢复合法位置。
2. 业务分类基础/字段与路由分别保存→空白新模板明确起点和节点→分类绑定精确模板版本→预览并导入→租户内分配→人工选择方式启动→结果保存→人工确认下一节点。
3. 同品牌线索总部/门店串行流转；有意向门店按可靠唯一映射，无意向仅当前总部管理员同次选店；未知/多匹配受阻。换租户/轮次不跳过整记录最近执行段结束及保存条件，原段首次补录不覆盖新轮。
4. 原电话作业与话后→原客户联系/业务历史回看；拒联保存进入当前租户公共禁呼，四类外呼检查，正常呼入保留。AI拒联由有权人员确认；专项范围/期限保留，管理员解除按本条来源和原因处理。
5. 原专业任务、资源、标签、通话与报表沿原入口复用；租户模块开通与成员授权独立。电话跨原Cloud页面保留，离开原Cloud范围/切租户/退出前完成本人通话、必要话后并离线。

## 验收方向
交付文件应可直接双击index打开、登录并切换有权租户和六入口；导航与数据不依赖运行时fetch JSON、HTTP服务或启动命令。专业模块所需资源本地打包，外壳/业务模型/路由统一使用一套实现，优先复用原组件。
必须核查登录与权限、原AI卡片及导入详情、业务分类/单模板/导入分配和线索接续、原电话与话后保护、公共拒联和专项、专业资源及原报表。字段、时序、失败/未知、重复提交及跨租户隔离按确认稿实现。
适用验证包括语法、资源闭包、隔离模型/DOM运行和获准页面验证。file自动验收既有拒绝保留，不能以HTTP结果冒充；无法实际打开的部分提供最小人工核验并如实列未验。旧通过状态不继承。
