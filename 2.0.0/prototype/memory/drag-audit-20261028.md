## 发现的问题

### DRAG-01 P2 分支标签重叠或在顶边不可见

定位：[flow-canvas-ui.js:14](/Users/huhaowen/Documents/038-云外呼平台/Demo_Protype_2/2.0.0/prototype/scripts/flow-canvas-ui.js:14)。

独立临时草稿中，处理节点连接到两个上下排列的结束节点，设IF和ELSE。1366与1600宽度下，标签基线仅相差10px、文字高度12px，实际相交2px。继续把源和一个目标节点拖到允许的顶边y=12，两条标签的基线都变为-3，文字底部位于视口顶部上方，无法通过向上滚动找回。稳定边ID和条件本身未改变。

原因是近距离边统一使用`min(from.y,to.y)-58`，没有文字边界钳制或多出口避让。建议基于真实连线、节点和文字包围盒分配标签位置，限制在可访问画布内，并对多出口做避让。

[标签重叠截图](/tmp/v2-drag-audit-20261028/labels-1366.png) · [顶边不可见截图](/tmp/v2-drag-audit-20261028/labels-top-edge.png)。精确矩形在持久JSON的`labels-ui.json`、`label-top-ui.json`。

### DRAG-02 P2 路由预览缺少职责与明确处理方式

定位：[flow-editor.patch.json:64](/Users/huhaowen/Documents/038-云外呼平台/Demo_Protype_2/2.0.0/prototype/scripts/flow-editor.patch.json:64) 中`routeTemplateDescription`。

实际保存的节点为`duty=HQ`、`methods=[MANUAL]`。独立路由预览不显示“总部”，也没有明确的“处理方式：人工”；只显示笼统的“由人员选择允许的方式”与状态域来源。当前处理方式已改为单选，该说明也容易被理解为运行时仍能任选。

R-196／AC-2134要求显示精确保存版本的节点职责与允许方式。建议逐节点读取该版本的`node.duty`和`node.methods`并明确展示，不用状态域名称代替业务职责和处理方式；旧快照仍按自身方法解释。

[实际预览截图](/tmp/v2-drag-audit-20261028/route-preview-duty-missing.png)。保存值和DOM全文在持久JSON的`route-preview-contract-detail.json`。正常路由13项检查只证明选择/保存/冲突/未知等交互通过，不能抵消这个精确内容检查失败。

### DRAG-03 P2 条件性缺口 损坏历史引用仍可先被标记清理成功

定位：[flow-template-cleanup.js:5](/Users/huhaowen/Documents/038-云外呼平台/Demo_Protype_2/2.0.0/prototype/scripts/flow-template-cleanup.js:5)，清理准入为第20行，持久写入为第28行。

仅用刻意构造的损坏台账复现：原记录引用缺失V999、引用版本含null节点、或同nodeId有冲突定义时，`catalogs()`仍返回success并写入一次清理标记，随后历史详情分别报VERSION_MISSING、STORAGE_ERROR，或取歧义首项。

原业务集合和快照字节均保留；这些引用错误在迁移前已经存在。**没有证据表明真实用户数据已损坏或丢失。** 缺口在于迁移前没有验证“历史引用可唯一解析”，便持久宣布清理完成。

建议在清理写入前验证实际引用版本存在、节点对象有效、nodeId唯一，以及记录/节点运行/执行段引用能精确定位。失败应返回明确待核且不写清理标记；不以当前单选或禁止循环的新规则改写旧模板语义。正常无损数据的清理、未来V1/V2及原记录保存检查已通过。
