# D联络云2.0.0 权限说明

[打开生产角色权限矩阵](docs/interaction.html)。原型顶部“说明文档”使用同一文件。

仅五种生产角色：超级管理员、租户总部管理员、租户总部运营、租户门店管理员、租户门店运营。

坐席为租户管理员或运营账号按需关联的电话作业能力，不作为角色。电话作业须满足当前租户模块、成员、作业权限、本人坐席关联、资源及状态条件；关联不扩大原有客户、报表、录音和导出范围。

AI充值办理管理仅超级管理员按原授权办理；五种角色均可按范围只读查看AI服务账户及充值流水。

本次已确认：

- 超级管理员：黑名单功能仅可按原范围查看，无手工新增、AI通话确认新增、解除及分组、号码、批量/同步维护权限；租户管理员和运营的既有权限保持。
- 总部/门店运营：在同一个黑名单页面沿用原AI分组、号码和操作规则，限本租户；客户拒联来源的解除仍由有管辖权的租户管理员填写原因办理。
- 总部/门店运营：无AI标签配置能力，有本租户AI业务场景权限；场景中使用已有标签不等于标签维护。
- 总部/门店运营：呼入接听能力以当前租户是否关联有效本人坐席为准，仍满足原资源及在线状态条件；呼入规则配置另行控制。
- 总部/门店管理员：有本租户通话记录核对、AI计费统计及原明细权限；计费统计不包含充值和调账。

- 总部/门店运营：可导出各自租户内原有权范围的云呼叫报表。
- 五种生产角色：均可读取/播放有权通话录音、读取有权号码明文；各角色原有数据范围保持。

2026-10-29 本轮修复：五种生产角色对有权通话录音的播放、暂停和进度调整按查看权限判断，不依赖页面编辑权限；仍核对当前租户、通话对象及录音可用性。本次修复本地播放器交互，既有权限和数据范围保持，验证以本轮本地录音播放器专项报告为准。

- 总部/门店运营：有本租户AI计费统计及原明细查看权限，充值和调账仍无权限。

- 总部/门店管理员：有本租户呼入规则查看、新增和编辑权限；本人坐席关联不是规则配置的前提。

- 总部/门店管理员：可导出本租户有权操作审计记录。
- 总部/门店运营：可查看本租户黑名单中的客户拒联来源，新增与解除仍按各自既有授权办理。

- 五种生产角色：均有AI服务账户及充值流水查看权限；租户角色限本租户，只读查看与充值、套餐办理、调账分别控制。

- 仅超级管理员有权办理试用/年包/话费包、手工调账/核对同次服务结果、服务汇总导出；其余四种角色无权限。AI服务账户和充值流水的原只读查看权限保留。

“导入与分配”归入业务&客户 → 客户维护；“呼叫拦截”在业务&客户区域作为独立一级菜单。呼叫拦截内的黑名单使用一个页面，保留原AI的分组、号码、有效期及供应商同步结构；在分组同步配置中兼容天润云呼叫，不再设置两类名单页签。同页按客户拒联等原记录来源控制新增和解除；运营的原名单维护权不包含客户拒联来源解除权，天润同步不自动扩大租户、账号或呼叫范围。

当前菜单分工：业务分类、业务字段和流转模板在业务管理；导入与分配、客户档案和AI线索回访记录在客户维护。AI业务场景与AI标签配置在呼叫中心的AI配置中，业务分类内仍保留原AI标签关联入口。AI服务与用量、AI充值管理在系统管理的AI服务分组；只整理入口，未增加功能或扩大管理范围。

三个矩阵分别列菜单、功能和数据范围，固定五种角色列；未明确生产细项标待确认。[坐席能力说明](docs/interaction.html#seat-capability)单列关联及使用条件。
