# 客户档案来源归集（Step55）

本轮依据用户“那修复这个问题？”修复客户档案的来源遗漏。客户档案改为一个客户列表，统一展示当前账号有权查看的业务、跟进和联系历史。原业务和专业记录分别保留，不创建第二份业务、通话或客户存储。

## 可见来源

| 来源 | 档案内容 | 详情入口 |
| --- | --- | --- |
| 统一业务账本 | AI、预外呼及人工业务、跟进段、真实通话、原字段快照 | 原业务、原跟进快照、业务通话 |
| 原云呼叫／预外呼 | 已导入客户、原通话、实际办理人、结果和导入分配历史 | 原始联系资料、原通话、原预外呼明细 |
| 原AI通话 | 原供应商结果、摘要、标签、原时间和已知时长 | 准确供应商及原通话标识的详情 |
| 原AI线索回访 | 原实际回访明细，或原来源仅提供的最近摘要与时间 | 对应原AI回访资料 |

同一租户及企业下的完整号码用于档案归集。脱敏号码、同名、相似时间或首项匹配均不能确认客户。无法确认的原记录单列待核，保留准确原来源入口。号码更正后，历史实际拨打仍留在当时号码下；新号码不会获得旧号码的通话次数。

业务跟进段、正常归档、原AI回访资料、通话记录及可确认拨打分别统计。受理、排队、未拨和回访汇总次数不作为实际拨打；未知时间或时长保持未记录。仅明确同一业务、执行段及通话标识的镜像可去重，冲突事实保留待核。

## 权限与原交互

各来源继续核对原模块、页面、租户、企业、账号及对象范围。原AI通话和原AI回访分别使用其原读取权限；运营不能因相同号码取得其他办理人的记录。已转出的业务使用本方截止历史，当前归集不补入后继租户内容。

查看原来源时再次核对准确引用及当前权限；读取期间切换账号、租户、企业、品牌或授权，旧结果不能回填新页面。来源读取中或失败会明确显示，其他有权来源仍可查看。查询与刷新不启动呼叫、同步计时器或写入原业务账本。原详情的编辑、再次联系和录音播放仍由原控制器核验。
