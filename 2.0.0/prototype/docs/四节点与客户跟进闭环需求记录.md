# 四节点与客户跟进闭环需求记录

日期：2026年10月29日。

状态：2026年10月29日用户授权“开始修改原型”，进入现有原型的S7定向实现与验证。首次八项封口及第二轮八项答复均已纳入正文；实现中的细节按推荐方案执行并事后留痕。本文不代表正式需求基线冻结或已经通过验收。

当前核心关系（2026-10-30增量）：分类定义字段并显式决定是否允许直接跟进（allowDirectFollowup缺省false）。导入整批明确DIRECT直接跟进或TEMPLATE按模板流转；DIRECT明确AI/人工/预外呼，AI场景必选，只豁免路由分流附加资料，基础必填、类型、映射和唯一性仍严格保留。DIRECT形成业务及独立直接周期，不建run/节点；TEMPLATE沿当前有效路由建立run。两模式实际办理/接听本人填写，新跟进读取最新定义和值并封当时快照，当前更正留痕。

适用口径：第1—16节中涉及“导入必建运行、首节点/路由判断、推进、转交、废弃运行和模板重开”的条款仅适用于TEMPLATE；DIRECT完整规则及其完成/再次跟进/后续启用流程以第17节为准。没有另行说明的业务身份、基础导入校验、租户/模块/本人权限、联系限制、实际通话、本人填写、当前更正和快照规则适用于两模式。历史章节的当次状态与验证结论保持原日期，不冒充本次执行结果。

## 1 确认范围与规划边界

1. 节点固定为开始、转交、呼叫、结束；不再重复选择节点类型，不提供独立分配节点或空白节点。
2. 跨租户办理顺序为先完成转交，再由接收租户分配跟进人和呼叫。呼叫节点不能隐式改变归属。
3. 客户维护中的导入与分配明确导入后的当前外呼方式；方式为AI时，必须在该入口选定AI呼叫场景。人员分配仍只选择跟进人，不重复选择坐席资源、AI任务、预外呼任务、机器人或线路。
4. 本功能按规划稿直接更新，不承担旧模板迁移或旧方案适配。正式运行产生的业务、跟进、通话、资料修正和转交历史仍应如实保留。
5. 新建及编辑配置读取最新业务分类，不提供分类V1、V2选择或人工版本确认。分类换绑只影响尚未启动的新运行；已开始运行只能按原流程完成或明确废弃，不切换流程、不重新定位到另一流程。新跟进的最新资料与本运行固定流程依据分开处理。
6. 本轮没有新增跨租户业务范围、权限角色或供应商能力承诺。

## 2 四类节点及唯一配置入口

| 节点 | 用户配置 | 运行职责 |
| --- | --- | --- |
| 开始 | 首个业务节点 | 默认生成且唯一；导入后定位首个业务节点，不增加一次人工启动步骤 |
| 转交 | 分流条件、目标承接方、转交后的节点 | 确认并完成负责租户变更 |
| 呼叫 | 承接方、单一呼叫方式、出口条件、下一节点 | 按当前安排办理呼叫和结果保存 |
| 结束 | 节点名称 | 满足当前办理要求后结束本次流程，保留业务事实 |

拖入组件即确定类型，属性面板不再出现类型选择。节点默认生成名称，允许改名。呼叫、转交、结束节点可按实际路径重复使用，开始节点保持唯一。

侧栏分支表和画布连线引用同一份数据：呼叫分支为条件与下一节点，转交分支为条件、承接方与下一节点。连线展示摘要，不能另存第二套条件。分支顺序表示优先级，默认路径置末；只有一个下游时可直接使用默认路径。

## 3 数据对象与业务身份

| 对象 | 身份和内容 | 关系 |
| --- | --- | --- |
| 客户档案 | 有权范围内的客户基础资料、各业务摘要和联系历史 | 一个客户可关联多条业务 |
| 业务记录 | 稳定业务身份、品牌、分类、业务编码、当前负责租户、跟进人、节点和当前字段值 | 一条业务可经历多个承接阶段和多次跟进 |
| 流程运行 | 同一业务下本次运行的唯一身份、捕获的完整流程方案及运行状态 | 新运行独立于此前已完成或已废弃运行；运行身份与节点身份共同定位办理位置 |
| 承接阶段 | 一段租户负责期间的办理过程 | 转交成功后形成接续阶段；转交本身不伪造一次客户跟进 |
| 跟进记录 | 某条业务本次实际办理的唯一身份及保存快照 | 同次办理的重拨继续关联此身份 |
| 通话尝试及通话记录 | 一次真实呼叫请求、供应商标识、终态和录音等事实 | 一次跟进可关联零至多次实际呼叫尝试 |
| 流转及资料变更事件 | 当次判断依据、动作、参与方、时间和明确结果 | 与原业务、阶段和跟进关联，不能覆盖原快照 |

新线索、冷线索以及不同媒体、门店来源的同品牌线索，以品牌和统一线索编码保持唯一业务身份。不能因分类或来源不同再建第二条可独立外呼的同一线索。

其他业务使用明确的业务类型域与业务编码识别，不扩大为所有业务编码全局唯一。手机号用于联系和辅助归集，不作为合并不同业务、字段或结果的依据。

重复导入默认返回已存在或冲突，不改负责租户、不覆盖跟进结果、不制造新流程或重开已结束业务。资料更新使用独立、受控的资料维护规则。

## 4 承接方与归属转交

| 承接方选择 | 解释 |
| --- | --- |
| 品牌总部 | 当前品牌唯一有效的总部租户 |
| 品牌租户中的当前负责租户 | 本条业务运行到节点时的负责租户；不是模板创建人或查看人的登录租户 |
| 品牌租户中的其他租户 | 同品牌内符合既有转交规则的其他有效租户 |

承接方是组织定位规则，不是管理员、运营或坐席权限角色。品牌共用配置不产生跨租户数据或资源使用权。

呼叫节点默认继承当前负责租户；上游转交已确定目标时，不要求重复选择。配置了特定承接范围的，进入该呼叫节点时必须满足该范围；不匹配时不能启动，也不能隐式切换归属。

转交的承接方在每条分支维护，节点顶部不再重复设置。目标和当前负责租户相同时，不生成跨租户转交结果或接续阶段，提示调整不适用路径。

转交明确成功时，负责租户、新承接阶段、后续节点、原分配清除和原方历史截止必须一致生效。接收方无需额外确认接收，但须按目标节点分配跟进人。失败保持原归属和真实执行状态；结果未知先核对同次办理，双方均不能重复执行。

本版沿用同品牌线索总部与门店之间的转交范围。有意向门店按准确编码唯一定位；无意向时按总部管理员原有权指派。门店间互转及普通分类跨租户不由本规划自动开放。目标不存在、停用、无法唯一定位时停留并提示，不能按首项或同名猜测。

## 5 分类字段与当前有效资料

自定义字段按品牌以及导入、填写两类用途独立管理；同名两用途分别保存身份和值。非空字段业务编码在同品牌同用途内唯一，导入字段业务编码必填，不设置格式配置项，字段类型及基本校验保留。

分类分别配置导入字段和填写字段两个Tab。字段库维护定义，分类维护引用、顺序、显示及入口必填规则。导入字段通过业务编码映射到对应业务字段；一次导入配置中一个目标只对应一列。

| 数据 | 维护与使用方式 |
| --- | --- |
| 原始导入证据 | 导入时保存批次、来源、映射、原始及规范化值；后续资料修正不覆盖 |
| 当前导入字段值 | 新跟进只读带出；只有正式资料维护或明确生效的同步结果才可更新 |
| 当前填写字段值 | 取本条业务最近有效保存值，新跟进可按权限修改 |
| 正式跟进快照 | 保留该次实际使用的定义、资料和最终结果，不能随当前配置重绘 |

资料维护必须有明确入口及独立的本条业务维护权限。记录来源、操作者、变更前后值、发生时间和生效结果；不能凭分配为跟进人就自动取得导入资料修改权，也不能通过填写同名字段冒充导入值修正。平台最新数据先指平台内已正式保存、生效的资料；外部实时取数不作已支持承诺。

缺少必须依赖的只读资料时，提示待补资料并引导有权人员补齐，不能让业务永久处于无入口可处理的待核状态。

字段和选项的稳定身份必须保持业务含义。相同身份只允许保持含义的文案调整；类型、用途或业务含义改变使用新身份。旧值不符合新定义时标待核，不自动清空、转换或按同名匹配。

导入必填只约束对应导入入口，填写必填约束对应跟进保存。新字段无值表示未提供，不直接视为明确空值，不因新增导入必填字段要求客服在只读表单补填。

## 6 导入与分配

导入确定来源及初始归属，转交改变负责租户，分配确定当前租户的责任跟进人。AI场景是本次AI呼叫安排的必要选择，不能再以自动取首项代替用户选择。

### 6.1 导入前置校验

整批先明确办理模式。DIRECT须分类显式允许并明确AI/MANUAL/PREDICTIVE，AI场景必选；DIRECT不要求路由或仅用于路由条件的附加资料，不建立run/节点。TEMPLATE仍要求当前有效路由与可判断首路径。预检失败不得静默改模式。

必须满足所选分类的导入字段要求才能确认导入，包括系统必需字段、分类启用导入字段的必填、类型及选项校验、业务编码映射和业务唯一性。未通过的行不形成可执行业务，不能先接收为待补资料记录再绕过校验。界面保留原名单及逐行原因，修正后重新检查。

本次正式提交范围内的每行均须通过校验；未通过的行不进入正式导入请求，不能静默忽略错误行或把它们计为成功。

TEMPLATE首次分流需要的附加资料，应在分类/流程配置时明确为本次导入必要项或提供合法可判断路径；DIRECT只豁免这一类路由依赖，不豁免分类导入必填。单纯选填字段未填不一律报错；但缺少必要判断依据、无法确定本次首个呼叫方式时不能猜测导入，须补齐必要资料或修复配置后再确认。明确无需外呼的合法结束路径展示无需外呼，不伪填一种方式。

导入时选择分类，初始负责租户为实际导入操作所在租户。界面明确展示与当前流程及首个待办理呼叫节点一致的外呼方式，分配时不再重复选择方式。首次节点需转交但后续方式已明确时，先按合法转交规则办理；具体门店待指派不等同导入必填不满足。

### 6.2 AI场景选择

当当前可执行呼叫安排的方式为AI时，在导入与分配入口必须选定当前实际执行租户有权、启用且与业务分类及呼叫节点适配的AI呼叫场景。

| 办理位置 | AI场景要求 |
| --- | --- |
| 导入后直接由本租户AI呼叫 | 导入界面选定场景，确认时与数据、方式一起校验 |
| 首节点先转交，再由目标租户AI呼叫 | 原租户不替目标选择或沿用私有场景；转交明确成功后，由目标租户在接续记录的导入与分配入口选本租户场景，再分配跟进人 |
| 同租户进入后续AI呼叫节点 | 有效且适配的原场景可带出确认；不适配时须在该入口重新选择 |
| 非AI方式 | 不要求选择AI场景，也不允许把AI场景带入人工或预外呼执行 |

场景按稳定身份和准确租户关联，不按名称或首项匹配。导入选择和分配列表维护同一份本次执行安排，不各存一份相互覆盖的场景值。跨租户转交后原AI场景安排失效，由接收方重新选择。

场景在本次执行发起前选择或更换；执行已受理后保留其实际场景和参数，不在执行中切换后复用同一执行身份。存在未核请求时先核对原请求，再确定后续安排。

场景内部的机器人、模型、线路、参数及执行策略由专业配置准备。用户选定场景后系统必须能解析出有效调用配置；缺失或冲突时提示准确配置入口并阻止起呼，不让跟进人在分配时再选AI任务或底层资源。本次选择不成为客户永久属性，跟进与实际执行记录保留当时使用的场景及真实调用来源。

预外呼继续使用预先配置且可唯一解析的有效执行方案，导入与分配页面不增加预外呼任务/队列选择。缺配置或多个方案冲突时先由有权人处理配置，不默认取第一项。

### 6.3 分配跟进人与办理顺序

| 首个业务节点 | 导入后办理 |
| --- | --- |
| 呼叫 | 方式明确，AI时场景已选，再选择本租户跟进人并等待办理 |
| 转交 | 先完成目标定位和转交，由目标租户按后续方式选场景及跟进人 |
| 结束 | 按合法路径结束，无需分配或安排呼叫 |

人员分配只选择跟进人。实际人工拨打人、预外呼接听坐席或AI执行主体由执行事实自动记录；跟进人不因被分配就获得本人坐席、资源配置或其他租户权限。谁接听谁填写的规则见第7.4节。

同租户进入下一呼叫节点时，责任人及原安排符合当前方式、资源、场景和权限要求的可沿用；不满足时重新核验。跨租户转交后清除原责任及执行安排，由接收方分配本租户跟进人。

批量安排按负责租户、当前呼叫节点、呼叫方式、AI场景及共同有效资格组织。一次为同组明确选择场景及跟进人，展示适用数量；跨组混选提示按组办理，组内任一行不满足则全组不写。分配不等于启动呼叫。

## 7 跟进开始 保存及唯一归档

### 7.1 一次跟进的边界

每条业务实际开始本次办理时生成唯一跟进身份，并绑定当前阶段、节点、方式及责任人；纯查看不生成新跟进。同次重拨、继续草稿或同次提交重试沿用这一身份。进入下一次实际跟进时创建新身份，重新读取最新资料。

AI或预外呼任务即使批量处理多条业务，也必须为每条业务分别建立跟进关联，不能把整个任务存成一条客户跟进。零通话的启动失败等办理保留真实原因，不虚构已拨打或已接通。

### 7.2 最新资料与固定运行方案

系统在运行正式创建并定位到首个业务节点时，将其标为已开始；导入成功已完成该定位的，即使尚待分配或尚未拨电话，也属于已开始。导入预览、尚未确认创建的准备不属于已开始，不增加人工启动流程按钮。

开始运行时捕获完整流程方案，包括流程身份、节点和出口、分支条件、承接关系及呼叫方式。分类换绑或随后编辑流程只影响未启动的新运行，不切换已开始运行。已开始运行只能在原方案完成，或按第10节明确废弃，不能通过重新定位、自动转类或替换节点切到另一流程。

每次新跟进仍读取本条业务当前绑定分类的最新有效字段定义和有权当前值，同时保留本运行固定的流程依据。资料和表单的取最新，不等于运行中的流程结构也跟着换。填写期间不静默替换控件、不丢输入、不改承接方或方式。

新字段、新选项及不改含义的文案可在新跟进中使用；会破坏原运行条件的字段变更须检查在办引用。原字段值与定义不兼容时保留事实并提示核对，不按同名或首项替代。无法满足原流程时，只能合法补齐其所需资料后原流程完成，或明确废弃，不擅自改出口。

正式保存使用本次实际读取和提交的内容，不能保存时重新取一份未展示资料拼成当时快照。数据或权限发生冲突时保留草稿并要求核对。重复导入不自动转类；本期不据分类换绑新增运行中重分类入口。

### 7.3 内容快照与当前值的同次保存

正式提交须同时保存本次跟进结果、完整内容快照、允许更新的当前业务值及保存状态，同次成功或失败。实际通话事实独立保留，不能因业务保存失败而撤销或伪装已经发生的通话。

快照包含当时字段名称、类型、业务编码、选项文案、表单规则、实际使用的导入资料、最终填写值、实际修改项、数据来源、业务/阶段/节点/方式/租户/责任人/办理人，以及开始和保存时间、关联通话。

当前值仅更新本次实际修改的字段。未操作保留；明确清空才保存为空；新增无值保未提供。迟到或旧阶段补录不自动覆盖较新有效值。当前有权人员主动更正时，直接保存其明确确认的当前字段值并记录前后值、原因、操作者和关联来源；提交前若当前值已被他人更新，应先展示差异重新核对。

### 7.4 唯一归档责任

| 办理情况 | 正式内容保存责任 |
| --- | --- |
| 人工外呼办理 | 实际通话办理人填写并提交，保留其账号和责任跟进人 |
| 预外呼及人工接听承接 | 谁实际接听谁填写；按本次实际接听坐席对应的平台账号提交，责任跟进人不因此自动改变 |
| 纯AI或预外呼最终无人工接听且无需人工补填的执行 | 系统在最终执行和必需结果明确后保存，记录系统来源和责任跟进人 |
| 所需人工结果或执行终态尚不完整 | 同一跟进保持待填写、待结果或待核，不另建第二条跟进 |

人工填写必填按真实人工参与及本节点适用范围执行；纯AI或最终无人接听的执行不强制伪造人工字段。若配置要求只有人工能提供的结果而流程没有人工参与路径，应在配置预检提示调整，不能自动把AI标签写成填写结果。

人工提交与系统执行沿用同一跟进身份。内容正式保存即保留其当时快照；系统在本次所需事实齐备后唯一标记归档完成。内容已保存与整次办理已完成分别表达，后续执行状态事件不能改写内容快照。

同一跟进只允许一次正式内容提交和一次归档完成。重复点击、断网重试或系统与人工并发以同次身份核对，不重复计数。正式保存后发现错误，无论是否已经归档，均由当前有权人员直接更新当前有效值并留更正来源，不重新提交或覆盖原内容快照，不新增一条正常跟进。界面不要求选择仅更正历史或另行申请采用当前值。

实际接听人从准确关联本次通话的跟进表单进入，仅能读取和填写本租户本次执行允许的资料；不自动获得该客户全部业务的权限。责任跟进人或管理员不能仅凭角色代替未参与通话的接听人填写。核对责任可以移交，但不产生代填权。接听人无法完成结果时保留结果缺失事实，由有权人核对执行并按原流程完成条件或废弃规则处理，不编造人工结果。

## 8 通话 执行结果及迟到回执

业务内通话在发起时就绑定业务、跟进、阶段、节点运行和本次执行尝试。收到供应商通话编号后精确关联，不能结束后凭手机号或当前指针猜归属。

每次真实拨打/重试分别记通话尝试，同一供应商事件重复推送去重。办理、完成跟进、实际拨打、接通及未执行异常分别统计，具体口径见第14.8节；不能只因生成跟进身份或收到第一条终态就计完成。系统归档主体、责任跟进人和真实执行人分别保存，不新增权限角色。

通话接通、终态、录音、业务填写保存和流程可办理状态分别表达。通话未结束可保留草稿；通话结束但保存失败保留待保存；内容已保存而终态待核时，不据此完成呼叫节点或推进流程。

迟到结果只能补充原通话及原跟进执行事实，不能覆盖较新值、当前归属或封存快照，不重新触发已确认流转。不同回执存在实质冲突时待核，不按最后到达的一条直接替换事实。

独立呼入和临时通话可进入有权客户联系历史；未明确业务关联时，不自动创建业务或猜挂某一条线索。后续明确关联须在有权范围办理，保留原通话事实。

## 9 条件判断 并发与确认提交

| 条件来源 | 生效依据 |
| --- | --- |
| 导入字段 | 已成功保存的有效导入值或资料修正值；无需先有跟进或通话 |
| 填写字段 | 对应合法正式保存的结果，或后续由当前有权人员明确修正后生效的当前值；每次判断固定其跟进快照/更正来源，不能读取草稿 |
| 通话状态和AI标签 | 对应实际执行结果及准确来源；受理不当作终态 |

导入可独立判断，也可与对应方式条件组合。AI提供通话状态与意向标签，人工/预外呼提供通话状态与填写字段。转交节点无需选择自身呼叫方式；多上游结果存在歧义时明确选择来源。

一次判断使用一致的数据依据，保存命中分支、字段/通话事实来源、后继节点和转交目标。确认前对实际提交内容重新核权、核归属、节点和事实状态；数据变化后旧确认失效，重新展示结果供确认，不静默换另一份最新值。

同一业务只能有一个有效进行中的办理执行；起呼、保存、推进、转交及更换跟进人统一检查当前业务状态和有效办理身份，防止两个窗口同时通过检查后分别起呼与转交。多端继续同次办理沿用原身份，历史查看不占用新办理。

请求结果未知或执行占用失联时，先核对原请求，不能当作通话已结束、解锁后重发或换新身份重提。办理门槛按动作分别判断，不能把人员或呼叫资源准备统一变成所有动作的前提。

| 动作 | 需要满足的前提 | 不增加的前置步骤 |
| --- | --- | --- |
| 条件判断 | 有权读取本次判断依据，按实际来源满足数据及状态要求 | 独立导入条件不要求先分配、通话或保存跟进 |
| 起呼 | 当前呼叫节点适用、人员及执行资格有效、AI时场景已选、资源有效；不存在冲突执行或待核请求 | 不要求再选择已由流程确定的方式或手选底层任务资源 |
| 转交 | 当前转交节点及分支适用、操作者有权、目标合法、无在途或未核执行，所需资料和结果明确 | 不要求原方或接收方先分配跟进人、选择AI场景或准备具体呼叫资源；接收后在呼叫办理前完成 |
| 结束 | 合法结束路径、无在途或未核执行、本次流程所需结果满足 | 无需呼叫的结束路径不要求先分配人员、选场景或伪造通话 |

未分配或呼叫配置不完整时，只阻止依赖该安排的呼叫办理；目标不合法、资料未知或真实执行未结束时，分别阻止依赖这些事实的动作并说明原因。以上例外不豁免权限、终态或必要结果完整性要求。

本租户有核对权限的人员可承接原请求核对责任，并记录交接和原因；该交接不改变业务归属、实际接听者或结果填写权。责任跟进人及有权管理人员可查看核对进度并进入升级处理。原接听人无法填写时，核对人只能补充核对及异常处置事实，不能冒充其填写。

已明确无执行请求的草稿可按权限释放或交接；有未知请求、在途通话、排队或重试时，只有可靠的未受理、已结束且不会再呼叫等证据才允许恢复。查无记录、时间超期、人工勾选或停止请求已受理均不能单独作为证明。无法核清时保持不可新起呼，但允许移交核对责任，不留下无人负责事项。

合法迟到结果补齐原同次当前办理、尚未确认流转且没有较新冲突事实时，可以恢复其结果状态并重新展示候选，由人员重新确认；不自动执行、不改原内容快照。已确认流转只追加证据。矛盾回执继续待核，不能以最后到达者覆盖。

条件命中只产生可办理路径，呼叫、转交及推进继续由有权人员确认。较高优先级条件待核时不进入后续或默认路径。保存跟进与转交分别反映实际结果；已保存而转交失败不能一起显示成功或伪装全部回滚。

## 10 客户档案 转交与再次跟进

客户档案按业务展示当前摘要和跟进时间线，阶段分组由系统记录，不要求用户手工选轮次。历史跟进读取自己的快照，不用当前分类字段重绘。各业务的当前结果、跟进次数、实际号码和归属分别展示，不能把售后结果覆盖为购车线索结果。

普通列表继续按更新时间倒序展示；原发生、正式保存与后续更新时间分别保留。业务有效值和当前结果按实际办理身份及有效来源顺序判定，不能直接取列表首行覆盖当前数据，避免旧回执补充后排到首行又成为当前跟进结果。

业务和跟进可查关联通话，通话可回看所属业务及跟进。客户改号不回改原实际拨打号码或通话归属。

转交后由接收方开始新跟进并读取当时最新有权资料。原方草稿不作为接收方执行安排或当前结果。原未保存结果若按原权限允许首次补录，固定归原阶段、原跟进和当时表单，不能读取下游新资料或覆盖接收方新值；新跟进才取最新。

结束只结束本次流程，保留全部事实。再次跟进须有权人员明确发起新的流程运行，从当前有效流程的开始定位；保持业务身份、原批次关联和当前负责租户，不回到最初导入租户。重新核验节点方式、承接范围、跟进人及AI场景，不借重复导入自动重开。原运行及其回执只归原运行，不混入新办理。

### 10.1 当前有效值直接更正

对已正式保存内容的纠错，当前具有本条业务资料/字段修改权限的人员直接更新明确提交的当前有效值，记录前后值、原因、操作者、发生时间及关联跟进，不再提供仅更正历史或申请更新当前值的二选一流程。

更正范围为当前允许维护的资料字段，不直接改变业务身份、分类归属、负责租户、当前流程节点、外呼方式、跟进安排或执行状态；这些内容分别沿其正式业务操作处理。档案当前摘要展示更正后的有效值，原跟进显示更正关联，打开原快照仍可查看当时原貌。实际资料更新时间与原快照保存时间分开记录。

原始导入证据、已保存快照、实际通话和办理人不回改。当前值更正不冒充原接听人的通话填写。原方在转交后没有目标当前值权限的，仍只能按原补录范围处理历史，不能绕过归属去更正接收方资料。

当前值生效使依赖旧值的尚未确认判断失效，重新展示候选；已完成的转交、结束或通话不回放。更正属于资料变更，不增加跟进或通话次数；提交时当前值已变化则核对差异，不能静默覆盖其他人的并发修改。

### 10.2 废弃与新运行

已开始运行只允许按其原流程完成，或由具有本条业务废弃操作资格的人明确废弃并填写原因。废弃不是删除业务、跟进快照或通话，也不是把运行换到另一流程。

废弃先停止产生新的执行安排；仍有在途通话、排队、重试或结果未知时，只能处于废弃处理中/待终止确认。取得实际结束、不会继续呼叫及必要收尾明确的证据后才可完成废弃、释放执行占用；不能以登记废弃代替执行终态。

原运行正常结束或废弃完成且没有未核执行后，才可由有权人明确建立同一业务的新流程运行，使用当前有效分类绑定和流程，从开始定位。当前负责租户保持，跟进人、方式、AI场景及承接资格重新核验；入口不适用于当前租户时先解决合法路径，不悄悄改回初始导入租户。旧请求和回执始终归旧运行，不因新运行获得新的执行权。

DIRECT同样遵守同业务串行、同号占用、所有联系限制、真实重试收敛、未知同请求核对、实际本人填写及唯一归档。责任跟进人与实际办理/接听人分别保存；管理员和责任人不能代填。当前资料更正依独立权限更新当前有效值并留痕，原段/通话/内容快照不改。DIRECT不提供模板判断、推进、转交、废弃运行或模板重开；不能借“直接”放开跨租户办理。

### 17.3 独立直接周期与明确完成

DIRECT正式导入生成首个directCycleId并追加directCycles，状态directStatus=ACTIVE。周期是直接业务办理边界，独立于流程run；一个周期可包含多次真实跟进和同次办理的重拨，每段始终归准确原周期。归档完成不自动完成直接周期，也不自动续拨。

“完成直接跟进”由有当前业务办理资格者明确确认业务结论。完成前所有旧执行、排队、重试、未知、冲突与必要本人内容及归档均须可靠收敛。当前周期至少有一段真实completedFollowup且归档；确实无需联系时可明确选择NO_CALL并填写原因，无真实完成跟进时不能以其他结论跳过。结论编码必须明确且非UNSPECIFIED，文案1—80字；结论、周期身份、来源DIRECT_COMPLETION、原因、操作者和真实时刻同次封存。成功后状态COMPLETED；不制造通话、跟进完成次数或模板END，旧段快照不变。

“再次直接跟进”仅在当前周期COMPLETED、分类仍允许且所有旧执行/必要归档收敛后显式办理。用户确认下一次AI/人工/预外呼方式，AI重新核当前本租户准确场景。成功时同一业务追加新directCycleId并设ACTIVE，保原周期COMPLETED及结论，清当前业务结论、旧责任跟进人和旧执行安排，再重新分配并明确起呼。不能复用旧周期身份、旧完成结论或旧通话充当本周期实际办理，也不创建run/节点。

### 17.4 在原业务显式启用流程

当前有权租户管理员可在DIRECT业务选择“启用流程”。当前直接周期可以ACTIVE或COMPLETED；不强制先执行“完成直接跟进”，只要求全部旧执行/排队/重试/未知和必要本人归档可靠收敛。

预检读取当前实际分类的明确生效路由、当前字段、当前有效资料和完整方案，验证基础必填、类型/映射/唯一性、当前首路径及必需路由资料。只按同一稳定字段身份复用值，缺资料由有权人通过受控补齐后重验。实际本租户首CALL为AI时本次明确必要场景；首节点先转交的仍由目标租户随后选其私有场景。无路由、资料缺失、来源未知或旧执行/归档未收敛时显示准确处理入口，保持原DIRECT，不重复导入或假建run。

enableFlowContext返回逐项issues及validationToken；令牌绑定record/revision/directCycleId/owner、当前分类字段和值、模板完整方案、入口及必要AI场景。正式enableFlow重新验证；任何变化使旧令牌失效，保用户输入重新检查。未知沿同次请求核对，重复确认不建第二run。

明确成功时在同一record/brand/category/owner下保存合法补充值及来源事件，handlingMode变为TEMPLATE，directStatus封FLOW_ENABLED，创建全新run并封当前方案、定位首节点及清旧责任安排。原ACTIVE周期记FLOW_ENABLED和结束时刻；原COMPLETED周期保原完成状态与结论。无需重复导入，原批次、直接周期、旧跟进、通话、资料更正、快照和全部历史保持。

新run按其准确节点职责重新安排、起呼、归档和明确流转。旧直接通话、标签、本人填写或完成结论不能满足新run的CURRENT_NODE/CURRENT_ROUND；显式HISTORY也只能按准确同业务/原租户来源及兼容授权读取，不等于完成新节点。当前首节点若为转交/结束，按其原职责办理，不被未分人或未场景错误拦住。

### 17.5 原型动作契约与独立验收

下表说明当前原型动作对应关系，不代表生产接口已验证。

| 动作 | 输入及必要依据 | 可观察结果 |
| --- | --- | --- |
| completeDirect | 明确outcomeCode、可选outcomeLabel、必要reason，准确当前业务/周期及修订 | 全收敛后封唯一COMPLETED周期与结论；无真实完成跟进仅NO_CALL+原因合法 |
| resumeDirect | 明确下一次directMethod及必要aiSceneId，准确COMPLETED周期及修订 | 同record新DIRECT周期，清旧责任安排，保旧结论，无run/node |
| enableFlowContext | 当前业务、可选补齐values及必要aiSceneId | 当前schema/值/首路径/逐项issues及validationToken；不创建run |
| enableFlow | 已预检values、必要aiSceneId及有效validationToken，准确业务修订 | 同业务显式创建TEMPLATE新run，旧周期/事实隔离，重复请求幂等 |

| 独立验收 | 应有结果 |
| --- | --- |
| 分类缺省/false及TEMPLATE缺路由 | DIRECT不可用；不能静默降级，无伪业务或run |
| DIRECT基础完整但缺仅路由附加资料 | 可按明确方式与必要场景导入；基础必填/类型/映射/唯一性仍严格 |
| DIRECT未选方式或AI未选场景 | 保名单具体报错，不确认、不自动取首项 |
| 同批一条基础校验失败或模式/方式改变 | 整批不可提交或旧预检失效，不漏行/不改模式 |
| DIRECT人工/预外呼实际人与责任人不同 | 实际本人填写，管理员/责任人代填拒绝，快照完整 |
| DIRECT拒联、同号占用、重试/未知或必要本人内容未归档 | 同原规则阻新执行与周期/流程转换，不伪造结束 |
| 无真实完成跟进直接选SUCCESS | 拒绝；NO_CALL+原因且全收敛可完成，不增加真实拨打或完成跟进数 |
| 已完成周期再次直接跟进并改下一次方式 | 新周期ACTIVE，旧COMPLETED结论保持，清责任重分人，不建run |
| ACTIVE已全部收敛直接启用流程 | 无需先完成周期；通过当前路由/资料/场景预检后同业务新run，旧周期记启用历史 |
| COMPLETED周期启用流程 | 保原周期完成结论，业务历史directStatus记FLOW_ENABLED，新run独立 |
| 启用预检后改变值/字段/模板/入口/场景或仍有旧待核 | 旧validationToken拒绝，保输入和原DIRECT，不重导入 |
| 同请求重复启用与旧DIRECT回执迟到 | 只建一个新run；迟到只补旧事实，不完成新CALL或覆盖新周期/节点值 |

本节规格维护只确认文档、引用与产品语义，不把静态引用核对当作业务运行测试。实际运行回归、浏览器证据与最终产品包由主实现流程记录。

### 17.8 双模式审计补充：实际人工通话证据

预外呼的坐席接听登记不等于客户接通；人工填写须同一真实拨打call的customerAnswered=true且实际接听账号准确匹配。相反的明确接通回执保原事实并待核，未知不推定已接通。 系统事实归档与人工内容保存分开，不能凭坐席登记生成虚假人工confirmed值；正常异步坐席先接听、客户后接通仍保留。
