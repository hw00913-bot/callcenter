# 生产角色权限矩阵

D联络云2.0.0 · 2026-10-29。HTML阅读入口：[生产角色权限矩阵](interaction.html)。

## 角色口径

固定五种生产角色：超级管理员、租户总部管理员、租户总部运营、租户门店管理员、租户门店运营。

坐席是管理员或运营账号在当前租户关联的电话作业能力，不作为权限角色。

AI充值办理管理仅超级管理员按原有授权办理；五种角色均可按各自数据范围只读查看AI服务账户及充值流水。

AI与云呼叫为业务模块，财务/资源管理为功能授权项，不单列生产角色。未明确权限不从原型预设身份推定。

✓ 已明确的职责权限；△ 对应功能授权/注明资格；— 不默认授予；无此权限 已明确不授予；待确认 未明确生产细项。

## 已确认的租户权限

- 超级管理员：黑名单功能仅可按原范围查看，无手工新增、AI通话确认新增、解除及分组、号码、批量/同步维护权限；租户管理员和运营的既有权限保持。
- 总部/门店运营：在同一个黑名单页面沿用原AI分组、号码和操作规则，限本租户；客户拒联来源的解除仍由有管辖权的租户管理员填写原因办理。
- 总部/门店运营：无AI标签配置能力，有本租户AI业务场景权限；场景中使用已有标签不等于标签维护。
- 总部/门店运营：呼入接听能力以当前租户是否关联有效本人坐席为准，仍满足原资源及在线状态条件；呼入规则配置另行控制。
- 总部/门店管理员：有本租户通话记录核对、AI计费统计及原明细权限；计费统计不包含充值和调账。

- 总部/门店运营：可导出各自租户内原有权范围的云呼叫报表。
- 五种生产角色：均可读取/播放有权通话录音、读取有权号码明文；各角色原有数据范围保持。

2026-10-29 本轮修复：五种生产角色对有权通话录音的播放、暂停和进度调整按查看权限判断，不依赖页面编辑权限；仍核对当前租户、通话对象及录音可用性。本次修复本地播放器交互，既有权限和数据范围保持，验证以本轮本地录音播放器专项报告为准。

- 总部/门店运营：有本租户AI计费统计及原明细查看权限，充值和调账仍无权限。

- 总部/门店管理员：有本租户呼入规则查看、新增和编辑权限；本人坐席关联不是规则配置的前提。

- 总部/门店管理员：可导出本租户有权操作审计记录。
- 总部/门店运营：可查看本租户黑名单中的客户拒联来源，新增与解除仍按各自既有授权办理。

- 五种生产角色：均有AI服务账户及充值流水查看权限；租户角色限本租户，只读查看与充值、套餐办理、调账分别控制。

- 仅超级管理员有权办理试用/年包/话费包、手工调账/核对同次服务结果、服务汇总导出；其余四种角色无权限。AI服务账户和充值流水的原只读查看权限保留。

## 坐席能力与账号关联

账号在当前租户以管理员或运营角色取得菜单、功能和数据权限，再按需关联电话坐席。坐席是电话作业能力，不单列生产角色。

租户总部管理员、租户总部运营、租户门店管理员、租户门店运营均可作为坐席关联的使用账号。关联后保留原角色；未关联坐席也可继续使用原有管理或运营功能。

电话作业同时要求：当前租户云呼叫模块已开通、账号与成员有效、本人有相应作业权限，且已关联有效坐席及所需电话资源。关联本身不等于电话已上线。

坐席关联按当前租户判断，切换租户后使用目标租户的有效关联；客户、报表、录音、号码明文和导出仍按原角色及授权范围。维护他人坐席关联的权限与使用本人电话的能力分开。

已确认租户运营的呼入接听能力以当前租户是否关联有效本人坐席为准；未关联不提供本人呼入作业，关联后仍按原电话资源和在线状态使用，呼入规则配置权限不随之开放。

云呼叫账号入口：系统管理 → 接入管理 → 云呼叫账号，沿原平台资源授权。

通话记录核对入口：系统管理 → 通话记录核对。核对资料缺失，沿原租户范围、状态与管理员权限；正常未接通/拒接仍在云呼叫记录查看。

- **N1 生产角色：**仅有本页五种生产角色。坐席是关联到当前租户账号的电话作业能力，租户管理员或运营均可按需关联，不作为权限角色。AI与云呼叫为业务模块；未明确的权限细项仍标待确认，不从原型预设身份推定。
- **N2 平台管理与业务选择：**超级管理员的组织与权限、接入管理全局读取，不受顶部品牌或业务租户过滤。业务、客户、呼叫和报表继续使用当前业务租户；相同品牌不自动共享业务数据或成员。
- **N3 账号与成员：**一个账号可在不同租户具有分别授权的成员关系；当前租户成员按总部/门店管理员或运营角色取得权限，并可按需关联本人电话坐席。全局账号资料和启停影响所有租户，成员角色、功能权限、坐席关联及成员启停按明确租户管理。总部/门店管理员只维护本租户成员，新增成员先明确目标租户。
- **N4 业务职责与流转：**租户管理员按本租户有权职责管理；运营还按分配、办理关系及有权历史读取。执行、转交、推进逐项核对职责、节点、版本和前段条件；转出后不自动查看下游当前资料。无意向门店时，同次指定门店并转交仅当前总部租户管理员可办理。
- **N5 坐席能力与电话作业：**坐席为管理员或运营账号在当前租户可选关联的电话能力，不改变角色及业务数据范围。租户运营的呼入接听能力以是否关联有效本人坐席为准；关联后仍满足原模块、成员、资源及在线状态条件。呼入接听与规则管理分别授权。未关联仍可使用原有非电话管理/运营功能；关联不扩大报表、客户、录音、明文及导出权限。退出、切换租户或业务域无需先完成通话、话后记录或电话状态核对，也不强制先退出电话坐席；普通未保存编辑仍按原有保存检查处理。
- **N6 财务功能授权：**五种生产角色均可按各自范围只读查看AI服务账户及充值流水；总部/门店管理员与运营也有本租户AI计费统计及原明细查看权限。已确认办理试用/年包/话费包、手工调账/核对同次服务结果、服务汇总导出三项仅超级管理员有权限，其余四种角色无权限；AI充值办理管理入口同属超管。各操作仍核原有权账户、产品、状态及数据范围。服务汇总导出沿当前分钟与服务信息口径，查看账户或流水不授办理及汇总导出权。
- **N7 资源功能授权：**总部/门店管理员已确认有本租户呼入规则查看、新增及编辑、通话记录核对，以及有权操作审计导出权限。配置维护不要求本人关联坐席；本人呼入接听另按有效坐席与原电话状态判断，运营关联坐席不授规则维护。平台和租户资源仍按原对象及状态管理，不因这些权限取得其他租户资源写入权。
- **N8 敏感内容：**已确认五种生产角色均可读取有权号码明文、读取/播放有权通话录音；总部/门店运营可导出有权云呼叫报表，总部/门店管理员可导出本租户有权操作审计。数据仍限各自原有权租户与对象；其他导出类型按对应矩阵项，坐席关联不另增范围。
- **N9 统一黑名单及原来源权限：**超级管理员仅按原有权范围只读查看，不具备黑名单维护权限。黑名单只有一个管理页面，保留原AI分组、号码、期限与同步结构，不再设置两类名单页签。客户拒联保留为分组内的准确来源，原有效范围和长期有效规则继续适用，正常呼入按原规则处理；本人电话作业成功保存明确拒联后关联同一分组，AI拒联仍须从有权来源人工核实。分组配置可增加天润云呼叫同步目标，按原同步授权、天润账号和支持的呼叫范围办理，回执未核定不显示已生效。运营保留原AI名单操作权；客户拒联来源的新增沿原独立授权，解除仍仅有管辖权的租户管理员填写原因，同号其他来源分别保留。
- **N10 分类与配置：**总部/门店运营已确认有本租户AI业务场景权限，无AI标签配置及供应商标签映射维护能力。使用已有标签和查看业务结果不等于维护标签配置。业务分类、共享字段、模板仍按有权品牌及配置授权维护，不因同品牌取得其他租户业务；原删除引用及历史保护保持。
- **N11 停用与收尾：**超级管理员管理全局账号停用；总部/门店管理员仅停用本租户成员。停用范围内禁止新操作，已接通电话及必要话后可有限收尾；此前已受理的租户任务按原条件继续，不自动转交。
- **N12 适用条件与待确认：**相应业务功能需模块已开通、功能已授权且对象/状态允许；电话作业另需本人坐席。平台管理不强绑无关业务成员或双模块资格。待确认项不是已授予，不凭本表开放权限；本次仅整理生产角色和既有规则，未重新定义未明确细项。

### 超级管理员

平台级管理；组织与权限、接入管理全局可见。业务查看仍按所选租户和监管职责，不因全局管理取得代办权。

### 租户总部管理员

管理当前总部租户的成员、功能授权和有权业务；总部身份不自动获得同品牌全部门店的账号或业务权限。 已确认具有本租户通话记录核对和AI计费统计权限。

在当前总部租户内办理获授权且有职责的业务，不自动取得组织、平台资源或财务管理权。 本租户AI黑名单权限沿用原AI外呼，有AI业务场景权限，无AI标签配置能力；本人呼入接听以当前租户有效坐席关联为准。 已确认有本租户AI计费统计及原明细查看权限。

管理当前门店租户的成员、功能授权和有权业务，不自动管理其他门店或总部。 已确认具有本租户通话记录核对和AI计费统计权限。
