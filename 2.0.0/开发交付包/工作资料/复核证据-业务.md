## 发现、整改及最终回读

| 发现 | 风险 | 整改核对 |
|---|---|---|
| 原单条主链把AI场景放在导入之后、把首转交放在呼叫／归档之后，标题含分类绑定而缺绑定准备。 | 可能实现成直接AI先导入再选场景，或首转交先制造一次呼叫。 | 已实际回读 FLOW-MAIN-DIRECT-CALL、FLOW-MAIN-FIRST-TRANSFER、FLOW-MAIN-AFTERCALL-TRANSFER。直接AI先选场景再预检／导入；首转交不要求不存在的执行段归档；呼后转交先从CALL确认进入TRANSFER，再重新判断并确认切归属。分类路由写为配置前置，ARCHIVE actor为系统。 |
| 接口定义配置与原段查询共用配置管理前提。 | 有原段填写权的普通实际接听人被错误要求具有品牌分类／字段管理权。 | 已实际回读 LOCAL-FLOW-INTERFACE-FIELD 与新增 LOCAL-FLOW-INTERFACE-QUERY。前者只配置定义；后者按准确本人原段、basis及本租户独立取数授权查询，无品牌配置权仍可合法取数，成功仅写草稿。两者各有独立CHECK。 |
| 原专业跟进“保存时按最新字段”措辞暗示临时换表单。 | 保存时拼入当轮未展示字段或值，破坏快照含义。 | 已回读 LOCAL-PLAT-PHONE-AFTERCALL：本轮开始取得并展示最新依据，保存沿当轮已展示／捕获定义；不临时换schema，并发不安全时保输入提示核对／重载。没有宣称生产begin-basis接口已实现。 |

接口页面已核对：UI-PAGE-2006、UI-PAGE-2223只关联接口定义配置；UI-PAGE-2203、UI-PAGE-2227关联原段查询。原段页的能力引用／参数映射只读，FIELD-FLOW-FORM-VALUES仅真实拨打／接听人于原段尚未正式保存时可填。FLOW-EXECUTION中的取数actor为实际拨打／接听人。

## 业务链与异常覆盖

| 检查点 | 回读定位 | 语义核对结果 |
|---|---|---|
| 参考与绑定 | TEMPLATE-CREATE/EDIT、ROUTE-BIND；TEMPLATE-REF-CATEGORY、ROUTE-MAIN、EFFECTIVE-PLAN | 参考只供编排；实际分类独立绑定同品牌兼容模板，只核真正使用的稳定字段／用途／类型／选项及准确AI上下文。当前为必选单模板更换关系，无解绑按钮。 |
| 分类与字段 | FIELD-CREATE/EDIT/STATUS/DELETE、CATEGORY-CREATE/EDIT；IMPORT/FOLLOWUP独立引用 | 同品牌同名不同用途分别保存；导入业务编码必填，无格式配置；引用保护和接口依赖闭包明确。更新时间排序不打乱字段、选项和条件顺序。 |
| 严格导入 | IMPORT-MAP/PREVIEW/COMMIT；IMPORT-TOKEN、IMPORT-ORIGINAL | 系统必需项、实际分类导入要求及首分流均满足才可导入；显式映射／别名一致／统一线索编码去重；正式范围全部通过。文件迟到或资料／分类／模板／字段／场景变化使旧确认失效。空名单依赖是中性提示，实际缺值／不匹配逐行阻止，不自动ELSE、不猜演示分流值。 |
| 运行开始 | IMPORT-COMMIT、RUN-ID、planSnapshot、REOPEN | 正式导入定位节点即建并冻结run，尚未拨打也已开始；预览不创建。换绑只影响后续新运行，当前沿原方案完成或废弃后受控再开。 |
| 分配及批处理 | ASSIGN、ASSIGN-BATCH、START-BATCH；FOLLOWER、ARRANGEMENT | 新流程只分配责任人及必要场景，不选坐席／任务、不改方式／owner、不自动起呼。批分配任一不合法全组不写；批起呼逐条反馈受理／失败／未知，已受理事实不伪回滚。 |
| 承接与场景 | AI-SCENE、START、SCENE-SNAPSHOT、原专业AI-SCENE-QUERY | 直接AI导入前明确本租户实际分类场景；首转交由接收方再选私有场景。需AI模块使用权，无需标签维护权；起呼重核资源及本节点、下游标签依赖。 |
| 执行及回执 | CALL-FACTS；attempt/provider/event/dialed/dialedAt/customerAnswered/retriesCompleted | 受理、拨打、接通、终态、重试收敛分开。事件归准确原段，重放不重计，相反事实保旧待核，终态不复活，旧段迟到不改新执行；同裸通话ID不跨域合并。 |
| 本人填写与快照 | SAVE-CONTENT、INTERFACE-QUERY、CORRECT；BASIS、CONTENT-SNAPSHOT、MODIFIED/CONFIRMED-FIELDS、VALUE-SOURCES | 实际拨打／接听本人填写；责任人、管理员、核对人不能代填。开始每轮取最新实际分类和值，保存沿原展示依据。已知预填可确认，未操作不等修改；absent不被默认空伪确认。更正只改当前值留源，旧快照不改；三方差异不能只换revision绕过。 |
| 归档及统计 | ARCHIVE、ARCHIVE-STATE、ARCHIVED、STATISTICS | 必要终态、重试结束、人工事实、内容及下游依据齐备才唯一归档。纯AI／明确无人由系统封真实事实，不造新人工字段确认；零拨异常可封存但不记completed或dial。流程END、接通、归档、业务达成分开。 |
| 判断与转交 | EVALUATE、ADVANCE、TRANSFER；两个确认token、意向编码及名称 | 高优先或组内必要来源PENDING阻后续／默认，不匹配留当前；IMPORT独立于方式，多值每行一值。总部下发依准确编码唯一定位，编码及名称皆空才可由总部管理员补选；仅名称／异常映射不得冒充无意向。门店上交唯一有效总部，无门店直转或普通业务跨租户。成功同次封截止、切owner/stage、清安排，不自动呼叫。 |
| 废弃、重开、转类、待核 | ABANDON、REOPEN、RECLASSIFY、REVIEW、HANDOFF | 在途／重试／未知时先ABANDONING，不假报完成释放新起呼。重开／转类须原run结束或废弃完成，最新配置建新run并保原业务ID、批次和旧事实。核对仅准确请求最小权限，不授整档案、代填或原动作重放权。 |
| 查询与历史权限 | QUERY、DETAIL、CUSTOMER-TIMELINE、HANDLER-INBOX；DEPARTURE-SNAPSHOT | 客户档案保业务跟进／原联系档案视图；同号仅归集不合并。转出方只看本方截止，辅助timeline/runContext同样裁剪；最小待填不扩整档案；超管监管只读不代办。 |
| 保留专业能力 | PLAT-CUSTOMER-IMPORT/ASSIGN、PHONE-AFTERCALL/CONTINUE、BUSINESS-API-IMPORT/RESULT | professionalCustomer／professionalFollowup两态、原专业任务和API指定坐席保持独立实体，不以其完成推四节点END／废弃；不因此恢复新流程“按坐席／任务分配”。独立呼入／临时通话不靠号码猜挂新业务。 |

上表FLOW局部动作均为LOCAL-FLOW-*，PLAT局部均为LOCAL-PLAT-*，字段定位为FIELD-FLOW-*。

“取最新”与“冻结”已明确：路径及依赖于run建立时封存；每次真实跟进basis取当时最新实际分类定义和当前值；正式内容与实际执行场景快照不重写。CURRENT_NODE/CURRENT_ROUND不借旧run；显式HISTORY仍须准确同记录、当前owner租户及兼容来源，未泛化跨租户历史权。

## current字段口径替换核对

prototype/memory/field-map.md已替换为当前逐字段表，不是将新规则附在旧正文后。最终回读有394条FIELD-*行、0条旧FLD-*表格行。文首明确四节点、参考／绑定分离、独立用途、导入业务编码必填、责任分配／必要场景，以及当轮快照和未来事实留存。

prototype/docs/field-alignment.json.mappings与最终plan的394个字段ID完全一致。逐项比对名称、entity/key、type/format、空值、必填、默认、校验、权限、生命周期、计算来源、保存及示例，未发现定义差异。原136个页面字段组仅在history.original_groups保留映射追溯，不替代当前字段规范。原专业预外呼坐席／外呼组参数有明确专业任务范围，不等于新流程分配目标。

current功能源保留43个FUNC ID，当前名称已采用“创建四节点流转模板”“分配本租户责任跟进人与AI安排”“在实际业务分类独立绑定单模板路由”“查看当前模板及绑定方案说明”。

## 结论与边界

在列明的主链、异常、权限、快照及current字段范围内，最后回读未发现仍未处置的业务语义冲突。主链顺序、接口取数权限的整改已在最终plan、页面绑定及产品检查中核对；原专业跟进latest时点也已明确。
