实际逐项复核了以下关键链条与权责：

1. 模板字段参考分类仅用于读取编排字段；实际分类路由由独立动作绑定当前兼容模板。当前分类与参考分类在字段定义、模板编辑、路由配置和实际导入中分别表达。用户不选择V1/V2；运行封存方案与当前配置分开。
2. 四节点为开始、转交、呼叫、结束。直接CALL、首TRANSFER、呼叫后TRANSFER三条主链分别说明，直接AI在导入检查前选择当前租户场景；首次转交不要求先打电话或制造归档；CALL先确认进入TRANSFER节点，再判断其承接条件并确认归属切换。归档动作由系统办理。
3. 正式导入全部纳入行须合法，字段和列映射、业务编码、首次分流及AI上下文与确认依据相连。分配只安排跟进人及必要AI场景；转交不继承旧安排，目标租户另行安排，没有自动起呼。
4. 真实受理、拨打、接通、结束、重试收敛、人工内容保存、系统归档、节点推进和业务END分别记录。零拨失败不算完成一次跟进或履行CALL；未知结果保同次请求核对。实际拨打／接听人填写，责任跟进人、核对责任人和管理员不能代理正式填写。
5. 本轮跟进开始捕获最新实际分类schema和当前有效值；保存沿本轮展示依据，不悄悄换schema或吸收未展示值。当前更正与旧段快照、转出截止分开；显式HISTORY依准确来源和当前兼容规则读取。
6. 原段本人接口取数与品牌字段定义配置已拆分。INTERFACE-QUERY只向准确本人提供有独立授权的取数能力，返回值仅进入本轮草稿；不要求品牌配置管理权，也不自动写客户有效值。定义维护仍须品牌配置管理资格。
