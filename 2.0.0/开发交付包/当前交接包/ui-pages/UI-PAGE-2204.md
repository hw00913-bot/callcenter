## 页面布局

- 关键词／实际业务分类／跟进安排筛选、按工作状态的队列与逐行业务列表
- 导入抽屉：实际分类、批次名称、格式模板／文件／粘贴名单、逐列映射及严格预检
- 导入批次回读、所选跟进人分配、明确批量起呼和本租户联系协调设置
- 导入抽屉整批选择“直接跟进 / 按模板流转”；直接方式明确AI / 人工 / 预外呼，AI显式选本租户场景。
- 列表显示办理模式；直接业务无流程节点，提供同租户办理和明确“启用流程”预检入口。
- DIRECT独立显示当前周期ACTIVE/COMPLETED及结论；“完成直接跟进”明确结论，无真实完成跟进仅NO_CALL+原因合法。
- COMPLETED提供“再次直接跟进”：明确下一次方式并重核必要AI场景，新周期清旧责任安排；启用流程只需全部执行/必要归档收敛，无需先完成直接周期。

## 页面状态

- normal：整批明确DIRECT/TEMPLATE；DIRECT由分类显式允许且方式/必要AI场景明确，仅豁免路由附加资料；两模式基础必填/类型/映射/唯一性仍逐行严格校验。分配仅选跟进人，AI场景在同一安排明确；不自动起呼。DIRECT列表无run/节点、无模板转交推进。

- loading：台账加载与文件读取分别标状态；新文件解析期间禁检查/提交旧名单，仅当前最新请求可更新当前草稿。

- empty：没有业务显示可导入或调整筛选；没有选中项禁用批量动作；尚未提供导入资料时中性提示参与分流字段，不提前报红。

- error：基础、映射、唯一性错误均具体到行；TEMPLATE路由资料不足提示修正，不自动降级DIRECT。DIRECT分类未允许、未选方式或AI缺场景均阻确认。模式/方式/场景变化使旧预览失效，失败保草稿，未知同请求核对。

- no_permission：超管只读监管；本租户管理员按导入／分配动作授权维护，运营不显示可办理的导入／分配入口，但可对有权同组AI／预外呼业务明确起呼。

- submitting：提交中固定当前准确对象和输入，不接受同一动作重复发送；真正成功后更新当前值/列表，失败保草稿，未知保准确同次请求并显示核对入口。
