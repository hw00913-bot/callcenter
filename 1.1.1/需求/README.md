## 当前字段配置

| 配置项 | 规则 |
|---|---|
| 填写方式 | 接口取数。 |
| 取数接口 | 选择超管已向当前租户开放、启用的接口条目；按名称识别，稳定ID引用。 |
| 是否使用其他字段作为条件 | 是／否；新字段默认否。否无需关联映射，门店独立查当前租户全部可用门店。 |
| 上游字段 | 条件开启时选一个已有接口字段；支持A→B→C，禁止自身、环、源定义不存在或类型不兼容。 |
| 上游取值字段 | 条件开启时从该能力声明返回属性中下拉选择，例如code。 |
| 下游入参字段名 | 条件开启时填写，例如seriesCode，预置默认可修改；不支持的参数明确提示，不静默查全部。 |
| 查询条件是否必需 | 必需／可选，独立于分类字段必填；新关联按能力默认（门店可选），旧门店绑定保留必需。 |
| 分类是否必填 | 分别设置，不因使用接口或依赖强制统一必填。 |

查询条件的“必需／可选”独立于业务分类字段是否必填。必需条件要求上游加入分类并显示且有效非空；可选条件允许上游不在该分类、隐藏或未填写时不传该参数而独立查询，有有效值才传，已填写但无效的值不能视为空来扩大查询。仍校验自身、循环、源字段定义存在、取值属性和参数类型兼容。新关联按能力元数据给出默认（门店条件可选），旧门店既有绑定兼容为必需。列表上游依赖显示无／必需·字段名／可选·字段名；分类只对必需依赖边逐级校验加入且显示，经过可选边不强制补齐，不自动加字段或改必填。能力元数据到真实协议的映射、特别是DCC必传sourceType的可信取得及真实租户范围，仍须技术核验。

字段编辑按填写方式、取数接口及查询条件顺序引导，并展示当前规则与下一步。字段保存先入库；加入分类仅进入草稿，另存分类才生效。缺必需来源可由运营明确点击补齐到分类草稿，不自动增加或改必填；取消分类不删除已入库字段。

这是简单的字段取值到查询参数映射；不配置任意URL、鉴权或脚本。超管继续只维护接口名称、研发预置取数能力、可用租户及启停四项。真实接口接入、返回属性声明及支持参数由研发维护。

## 已确认：门店联动使用边界

- 选择唯一有效意向车系后才查门店，必填仍按分类分别设置。
- 当前车系门店查询失败或不完整时保留输入、提示重试，查全后才允许新的门店选择；失败不证明旧门店失配。
- 待重选门店重新匹配后，客服再次确认或选择才恢复有效。
- 接口停用／当前租户被撤权时，未提交值保留显示但不作有效值，旧请求返回数据不再用于新选择；选填可手动清除后保存。
- 清空本次意向车系后，保留原门店并标记待重选。
- 来源重新可用后，旧值按当前条件重查，匹配且经客服确认后恢复有效；车系与门店分别校验。
- 每个本次意向字段保存编码和当时名称，历史名称不随上游改名变化；原始导入信息单独保留。

用户已说明暂时没有车系和门店接口资料，先继续需求讨论（SRC-146）；真实接口状态仍为待核验。搜索词或当前分页未显示某家门店，不足以认定已选门店失配。

## 已确认：按具体车系查门店

唯一所选车系编码交给权威接口查询，以其完整返回门店为准，同时遵守NEV／ICE对应规则；不自行扩展为同体系全部门店，也不维护人工关系表（SRC-151/156）。

### US-013 · 超管新增业务数据接口条目

角色：超级管理员。目标：新增可供租户字段引用的业务数据接口条目

- **AC-105**：平台提供可供字段引用的业务数据接口字典；超管仅配置接口名称、取数能力、可用租户、启用状态。名称可自定义，取数能力从研发预置的可用能力中选择；条目内部标识由系统自动生成，无需手工填写。
- **AC-106**：业务数据接口字典由超管统一维护，租户侧引用已提供的条目。
- **AC-127**：超管填写名称、选择预置取数能力、勾选可用租户并设置启停状态后，能够保存新的字典条目；使用受启停与租户授权约束。接口地址、请求方式、鉴权、请求参数及返回字段映射由研发预置，新增尚未接入的能力需先由研发接入。
- **AC-131**：已被字段配置引用的接口字典条目保留；编辑、启停或租户授权调整不自动删除条目、原引用配置和历史已保存数据。

讨论边界：超管仅配置名称、预置能力、可用租户及启用状态；技术对接由研发维护。 新增、编辑、启用、停用和租户授权继续按各自业务结果拆分；字段数量不新增独立功能。 已引用条目固定取数能力（SRC-150）；未引用条目的能力编辑、名称重名与同一能力多条目细节留待规格。

### US-014 · 超管勾选接口条目的可用租户

角色：超级管理员。目标：为接口字典条目勾选可用租户

- **AC-107**：超管能够为业务数据接口字典条目勾选可用租户并保存。
- **AC-108**：租户新增字段引用时，仅可选择已向该租户开放的接口条目；授权撤销后的新查询／选择及历史配置处理见AC-122、AC-123。
- **AC-122**：超管撤销某接口对某租户的使用授权生效后，停止该租户对该接口的新查询和新选择；作用范围限定为当前接口与租户，不全局停用接口或影响其他有效授权。
- **AC-123**：撤销后保留历史已保存数据及既有字段配置，当前租户相应接口引用显示不可用；尚未提交的选择保留显示并提示“来源不可用”，不作为有效值提交，旧请求返回数据也不再提供新选择。选填项可由客服清除后保存，必填项沿已有规则；不禁用整个表单。

讨论边界：授权范围与现有成员权限分别生效；不扩大给所有租户成员。 撤权后在途及未提交值按SRC-148；重新授权仅恢复查询资格，旧值按SRC-149重查并由客服确认。

### US-015 · 业务分类字段引用接口作为数据来源

角色：具备现有字段配置权限的人员。目标：为字段选择接口取数方式并从字典引用可用条目

- **AC-109**：字段配置支持选择“接口取数”方式，使用字段时通过所引用接口获取候选数据；本次意向车系与门店使用新增字段，不替换原计划到店字段。
- **AC-110**：配置接口来源时从业务数据接口字典选择可用条目，按接口名称识别、按稳定内部标识保存引用；门店字段只关联唯一的本次意向车系字段。接口地址、鉴权、请求参数及返回字段映射由研发预置，配置人员无需填写。
- **AC-111**：新增本次意向门店字段的候选数据来自对接系统的专营店数据，不能自行维护为自定义门店选项；不将原计划到店门店文本字段直接改为接口字段。
- **AC-120**：意向车系和意向门店沿所属业务分类分别配置是否必填；门店必填时至少选择一家有效门店，选填可空。未接通仍沿原有条件必填规则，已经填写的每一家门店仍须有效。
- **AC-121**：接口取数方式及车系—门店联动不将两个字段统一强制必填；字段的必填要求依据当前业务分类分别生效。
- **AC-124**：本次仅一个本次意向车系接口字段且为单选，不提供备选车系；本次意向门店为多选，只关联该车系字段，不支持多个车系字段作为查询条件。

讨论边界：配置采用接口取数＋字典选择＋唯一意向车系字段关联；技术参数由后台预置。 分类字段配置与本次客户值填写为不同操作，不新增通用参数编排。 新增本次意向字段，保留原计划到店字段；空车系查询前置已明确，编码和名称按各字段保存，具体结构待契约核验。

### US-016 · 查找并选择同体系的意向车系与门店

角色：具备业务信息填写权限的运营／坐席。目标：查找权威车系与门店，并按NEV／ICE规则得到匹配候选

- **AC-112**：本次只保留一个可搜索单选的意向车系字段；本次意向门店使用独立弹窗勾选多家，确认才整组带回，取消不改原值。筛选或重查保留仍有效的暂选；候选限当前车系完整权威结果并去重，不新增跨车系查询或选店上限。原计划到店字段和导入原值保留，真实接口及多门店保存契约仍待核验。
- **AC-113**：所选NEV车系以其唯一编码查询权威接口返回门店，候选限定为NEV门店；不自行扩大为全部NEV门店。
- **AC-114**：所选ICE车系以其唯一编码查询权威接口返回门店，候选限定为ICE门店；不自行扩大为全部ICE门店。
- **AC-115**：查询或配置缺口不得通过自行创建门店选项替代权威来源；查询失败导致必填无法完成时见AC-132、AC-133，其余异常保存细则待讨论。
- **AC-116**：保留本次记录的原始意向车系和门店信息；本次填写不覆盖原导入值。
- **AC-117**：将原始意向对应的匹配信息带入本次填写时，需要客服明确确认；未确认不得按本条规则自动带入。匹配校验及确认控件待细化。
- **AC-118**：本次意向车系变化后，按新车系的完整权威门店结果逐家核对整组选店；仍匹配的原有效门店可保留，失配门店保留显示并标记待重选，不默删或作有效值提交。只影响本次组合，不停用目录门店或改写历史记录。
- **AC-119**：逐家处于待重选的门店不作当前车系下有效值提交或回传；客服重新勾选当前有效候选，或待重选门店重新匹配后经明确确认才恢复有效。多选中存在无效项须处理或手动移除，不能静默过滤保存；本条不新增必填要求。
- **AC-125**：门店查询仅读取唯一的本次意向车系字段的一个有效编码，以权威接口完整返回的门店为候选，保持NEV/ICE对应；不执行多车系结果并集，平台不另建车系—门店关系表。真实按编码查询及完整性能力仍待核验。
- **AC-126**：切换本次意向车系后，按新车系完整权威门店结果逐家判断已选门店；未查全时保留显示，不能沿用旧条件有效性。仍匹配的原有效项保留，失配项待重选；待重选项再次匹配也须客服明确确认或选择后恢复，不默删任何旧项。
- **AC-132**：接口查询失败导致当前分类要求的必填信息无法完成时，保留已填草稿供重试，不能通过临时自定义门店替代权威来源。
- **AC-133**：正式完成保存按原通话条件和分类必填校验：门店必填至少一家有效门店，选填可空；未接通空值豁免仍沿v1.1.0准确条件。已填整组门店逐家校验，存在无效项不能因另有有效项而提交，不静默剔除；不能因任意一次查询失败一律阻止本来仍有效的保存。
- **AC-134**：本次意向车系未选择或未有效确认时，门店提示“请先选择意向车系”，不发起门店查询；选中一个有效车系后仅读取其编码查询。该前置条件不改变车系与门店按分类分别设置的必填规则。
- **AC-135**：当前车系的门店查询失败或结果不完整时，保留已填内容并提示重试，完整成功后才允许新的门店选择；不以查询失败或不完整判定旧门店失配。现有值能否提交仍按当前条件有效性及原保存规则校验，不因一次失败一律禁存。
- **AC-136**：清空本次意向车系后不查询门店；整组已选门店保留显示并逐家标记待重选，不作有效值提交或回传。重新选车系后按当前完整结果逐家核对，经客服明确确认或重新选择才恢复有效。
- **AC-137**：接口重新启用或租户重新获得授权后，尚未提交的来源不可用旧值须按当前条件重新查询，确认仍匹配并由客服明确确认或选择后才恢复有效；失败、部分失败或不匹配不能直接恢复。已保存历史不受影响。
- **AC-138**：正式保存唯一所选车系的编码及当时名称，门店保存去重后的整组编码与当时名称数组。逐家校验来源及当前车系匹配；旧单门店值兼容读取为一项，历史已保存内容不改写。通话详情展示该次快照，客户档案使用同一通次的车系与整组门店快照，不跨通拼接；当次门店为空也不继承旧店。原导入信息和原计划到店字段分别保留。

讨论边界：原导入信息和原计划到店字段保留，本次选择由新增意向字段承载。 选定唯一意向车系后才查门店；部分失败查全后再新选；待重选恢复须客服确认；清空本次意向车系保留原门店待重选。 来源不可用的未提交值与在途结果按SRC-148处理，必填仍由分类和原保存条件决定。 单车系门店范围以编码查询权威返回为准（SRC-151）；搜索或当前分页未显示不能证明失配。失败保输入已有本地设计证据（SRC-152），真实查询完整性、保存与生产草稿契约仍待核验。

### US-017 · 超管编辑业务数据接口条目

角色：超级管理员。目标：修改并保存已有接口条目的可编辑属性

- **AC-128**：超管能够修改并保存接口名称；内部标识及已有引用保持。条目被业务字段引用后，绑定的取数能力固定；需要更换时新增字典条目，再调整字段引用，原条目和历史保留。启停与租户范围仍可按各自操作调整。

- **AC-130**：超管能够停用接口字典条目，保留条目、既有引用配置和历史。对应未提交选择保留显示并提示来源不可用，不作有效值提交；旧请求返回数据不再提供新选择。选填项可由客服清除后保存，必填沿已有规则。

讨论边界：停用保留引用与历史，在途与未提交值按SRC-148处理；启用仍为独立状态操作。
