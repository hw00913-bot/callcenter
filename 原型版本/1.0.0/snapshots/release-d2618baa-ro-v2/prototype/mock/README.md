# 演示数据

数据包：`alicti-showcase-v1`，用于当前 AliCti 原型。打开原型后自动加载，不需要先点“准备演示”。业务规则沿用当前接口采用口径，所有新增数据均为虚构，不连接供应商。

## 覆盖内容

| 模块 | 本轮补充 |
| --- | --- |
| 账号、租户、坐席 | 复用总部王静、门店周岚的账号和租户关系；新增 8 个坐席，提供启用、停用、离线与可用状态；保留已保存的账号绑定 |
| 技能组 | 2 个逻辑模板、4 个租户独立技能组；坐席可关联多个组，技能等级使用 1–10 |
| 线路、号码、呼入 | 2 条虚拟线路、2 个授权号码、2 个号码池候选、2 条呼入规则；售前与售后分支分别关联本租户技能组 |
| 人工呼叫配置 | 总部与门店的人工外呼、呼入配置各一套，共 4 套 |
| 预外呼、自动外呼 | 保留少量待启动、运行、暂停、结束与本任务再次联系样例；演示样例按模块压缩到 15 条以内 |
| 导入、分配、客户档案 | 保留少量线索、售后、活动样例及其批次、客户关联；演示样例按模块压缩到 15 条以内 |
| 通话记录 | 保留人工、预外呼、自动外呼与呼入的少量话单及接听结果样例；演示样例按模块压缩到 15 条以内 |
| 统计报表 | 七类报表含线索成效；通话类按可见话单聚合，任务累计采用独立官方结构样本。线索样本覆盖同码跨批、同号异码、缺码和六项业务资料 |
| 录音、通话文本 | 保留唯一既有合成语音与 RASR 文本样例 `CALL-MAN-1001`，移至本演示日便于查找；其他新模拟通话不冒用该音频 |
| 配置记录、异常、审计 | 新增成功/失败配置记录、任务和通话结果待核对数据及操作审计；失败不阻断正常样例 |

以上是新增数据量，不包含原有基线、旧展示样例和操作过程中产生的记录。

## 推荐演示路径

1. 刷新原型，用超级管理员进入 `7522240` 的云联络中心。任务列表可直接看到“总部·试驾邀约”“上海门店·保养提醒”等样例。
2. 先暂停同一服务团队正在执行的任务，再启动待启动任务或继续暂停任务；按同 enterpriseId 与实际 cno 检查预测任务占用；同名或不同技能组中重叠坐席也不能绕过占用。
3. 在任务详情查看预置的客户进度、通话记录和报表，演示启动、暂停、继续与结束。业务页面不再展示逐条模拟结果的操作栏；底层模拟方法保留，结束任务后仍阻止后续执行。
4. 在“导入与分配”选择今日线索、售后或活动批次，演示客户分配；通过“演示工具”切换王静或周岚，可进入对应坐席工作台。
5. 在通话记录查看 `CALL-MAN-1001`，演示合成录音播放及对话气泡文本。纯自动外呼不挂人工坐席或套用录音。

### 本版新增演示路径（2026-09-16-consolidated-2）

- 关联坐席的租户运营进入坐席工作台；上线后使用“模拟呼入来电”或“模拟预外呼分配”，在右侧待接听面板接听并保存处理结果。特殊情况放在默认收起的更多场景；正常入口会复位上一次的失败设置。
- 原任务再次联系：总部与上海门店各有“本任务再次联系”暂停任务，每个任务4条已接通来源，其中2条为坐席已接听并约定再次联系，2条为客户接通但坐席未接听。从对应任务的“待再次联系”或任务客户页选择后“加入本任务”，核对原任务ID、任务数量不变，新增执行条目而原历史保留。全局客户档案存在多个来源任务时须先选任务，不跨任务混合。已结束的旧样例只保留历史，不可再次安排。刷新只补缺失演示数据，不清除已保存结果或安排。
- 超级管理员在号码管理点击“从 AliCti 导入”，查询和跨页选择 `number-onboarding.js` 的候选号码，确认线路和方向，再设置本地使用坐席范围。停用候选可导入，但仍保持不可外呼。
- 处理结果的计划到店门店可输入任意名称或留空；保存后核对通话、客户档案与线索成效，报表可按门店名称包含搜索。

接听通知、来电失败、号码列表响应与联系任务均为本地演示。接听、再次预外呼和号码导入新增的保存状态可刷新恢复；不需要清空已有演示数据。全部本地检查入口为 `python3 qa/run-offline-checks.py`。

## 文件与加载顺序

| 文件 | 作用 |
| --- | --- |
| `demo-kit.js` | 同一演示日固定时间锚点、ID 前缀、安全增量写入辅助 |
| `demo-resources.js` | 坐席、技能、线路、号码、规则及审计的关联数据 |
| `demo-activity.js` | 任务、客户批次、话单、在途状态和业务来源快照 |
| `demo-media.js` | 保留既有合成音频/文本样例并调整其展示日期 |
| `demo-install.js` | 按现有状态归一组件处理样例，再合并客户与任务结果存储 |
| `report-fixtures.js` | 线索编码、批次、通话和业务资料的专项样本 |
| `report-summaries.js` | 官方任务累计样本；与当前话单汇总分别管理 |
| `demo-ready.js` | 原有恢复流程结束后，核对并恢复已经提交的演示话单修改 |

资源和活动在业务组件之前生成；安装器在状态归一组件之后、应用恢复之前执行；最后核对在导航之前完成。入口已经配置好顺序。

## 日期与已有数据

资源 ID 使用 `SHOWCASE-` 前缀；任务、客户、话单 ID 还包含当天日期。同一天刷新不重复生成；次日首次打开补入新一日数据，让今日与近 7 日查询继续有样例。旧记录保留，不自动删除。

账号、坐席、任务、客户已有修改优先。新增数据只补缺失 ID；损坏或重复 ID 的存储保持原值。话单修改须能匹配同租户、同任务、同客户的已提交结果和批次历史，才恢复到页面。没有批量清空或覆盖用户数据的动作。

可在原型目录执行 `node qa/verify-demo-fixtures.cjs` 核对关联、权限、状态、报表和存储；仅验证本地演示，不代表真实接口联调通过。

线索成效日期按可见来源批次的首次导入选择线索，展示所选线索的全部可见历史；客户档案仍沿用手机号维度。原生日/坐席/队列纯适配器与供应商真实接入分开验证。
