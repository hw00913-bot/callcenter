# AliCti 接口与当前需求契合度分析

日期：2026-09-11。结论性质：独立文档核验与迁移差异评估；未调用业务 API，未进行真实拨号、配置或联调，未更新原需求事实、门禁与冻结包。

## 负责人补充：账号 ID 与坐席（2026-09-11 最新纠正）

来源：用户最新转述负责人确认——**enterpriseId 就是供应商账号 ID，UUID 不会在接口中用到**。本说明取代此前“UUID 是接入凭证”和“enterpriseId 等于 UUID”的解释；这些旧解释不再作为本轮评估依据。

| 对象 | 当前评估定位 | 对现有需求的影响 |
|---|---|---|
| enterpriseId（供应商账号 ID） | 承接原“实例”的供应商资源归属范围 | 租户、坐席、号码、任务的原实例引用映射到供应商账号；历史记录保留原供应商标识 |
| UUID | 不参与本次接口接入 | 不增加 UUID 参数、凭证配置或 UUID 鉴权待办 |
| cno（坐席工号） | 供应商账号下的呼叫执行身份 | 以供应商账号上下文定位坐席，保留平台登录账号与本租户坐席的一对一关联 |
| 平台租户 | 总部/门店的业务权限和数据隔离范围 | 租户与供应商账号建立映射；同账号下多租户的资源隔离仍需验证 |

关系口径：平台租户 → 供应商账号 enterpriseId → 坐席 cno；平台登录账号 → 本租户坐席绑定。供应商账号与平台人员登录账号分别管理，不预设租户与供应商账号一定一对一。

鉴权按公开文档的企业编号方式理解：validateType=2，使用 enterpriseId、timestamp、sign；sign 按 enterpriseId + timestamp + 部门 token 计算。enterpriseId 是标识，token 用于签名；无需引入额外 UUID 凭证。坐席前端仍按文档申请短期 sessionKey。[接口鉴权][S01][坐席登录][S03]

这项确认解决了原 SC-001 的“账号 ID 对应哪个字段、实例由什么替代”问题。后续评估采用 enterpriseId 替代实例的资源映射；保留账户下资源隔离、实际权限、事件补偿和业务闭环的 POC，不再要求负责人解释 UUID 请求位置或 UUID 轮换机制。

本次只修正接口评估报告，未改原型、正式需求基线或门禁状态。

## 1. 结论

**AliCti 具备承接当前云联络中心主要呼叫能力的基础，但不是原阿里云 CCC 的接口直接替换。业务能力方向较契合，资源与权限模型、任务调度和数据闭环需要实质适配；当前证据不足以认定全量迁移可行或给出可靠工期。**

人工外呼、自有坐席工作台、预测外呼、自动 IVR、通话查询、录音下载和 ASR 都找到具体文档。核心阻碍不是有没有“拨号接口”，而是能否保持当前的租户隔离、同号跨批次归属、在途通话保护、接通判定与统一报表口径。

“软电话工具条”文档提供 JavaScript 对象方法，可以作为自有工作台的底层接入候选；这不要求恢复已取消的外部业务系统 PhoneBar。厂商 SDK 名称与本项目取消的产品入口是两个概念。[快速入门][S02]

不计算单一契合百分比：26 个场景的复杂度不同，且租户隔离等关键项尚待验证；“找到同名接口”不代表验收通过。当前更准确的判断是：**可进入条件化 POC，尚不能宣布等价替换或生产可用。**

## 4. 必须处理的迁移差异

### 4.1 鉴权、会话与权限

原 CCC 身份/SDK 接入须改为 AliCti 的部门或企业签名与 cno 身份映射。签名时间戳按秒、有效 30 分钟；登录 sessionKey 只有 30 秒有效，这两个时限不可混用。[S01][S03]

建议平台后端校验“当前账号—当前租户—坐席”后申请短期登录材料；长期 token 不进入浏览器。保留工号字符串，避免丢失前导零。鉴权页与登录页对部分类型描述不同，需统一解析数字/字符串返回。

按负责人最新确认，`enterpriseId` 就是供应商账号 ID，在迁移方案中承接原实例；平台总部/门店租户保留独立映射，不能将 `departmentId` 自动视为平台租户。企业 WebSocket 默认接收所有坐席事件，每企业最多 10 条连接，支持按坐席订阅；这要求集中后端接收并按权限分发，不能给每个租户浏览器一条企业全量流。[S16]

### 4.2 自有工作台可以保留，但 SDK 生命周期要替换

建议顺序：平台资格校验 → CTILink.setup 完成 → 注册事件 → 申请 sessionKey → Agent.login（软电话 bindType=3）→ 核实电话状态 → 可呼叫。前端维持当前工作台和联系弹窗，不恢复外部 PhoneBar。[S02][S04]

静音是 `Session.mute` 切换操作，重复调用会取消静音；应按已知当前状态调用，并验证 in/out 方向与用户“静音麦克风”的含义，不把超时重试当成幂等操作。[S19]

文档提供下线及页面关闭示例，但不能据此承诺关闭浏览器一定成功下线。当前通话/未保存话后仍需平台保护，服务端清理和跨设备互斥须实测。文档历史浏览器与 HTTP 示例不是当前生产兼容性证据。[S02][S04]

### 4.3 任务状态和资源限制不是一一对应

`type=1` 预测外呼是当前“客户先接通再分配坐席”的候选；不要把 SDK 的“预览外呼”误认作这一批量任务。`type=2` 自动外呼是 IVR 候选，也不能和单独的“座席自动外呼”目录混为一类。[S04][S05]

明确差异：

- 一个坐席只能加入一个运行中任务；一个外呼组可绑定多个任务，但只能同时在一个任务运行。启动时须核查，不能仅看坐席当前空闲。
- 预测任务最小可用坐席数默认 10，允许 1—10；小门店不能照用默认配置，否则可能自动暂停。这不是“必须买 10 个坐席”的证据。
- 连续暂停默认超过 30 天自动结束，结束后不能再启动；企业可配置跳过。要保持现有继续任务体验，需核定部署配置，或明确显示厂商结束原因。
- `autoStart`、名单 `importTelAutoStart` 应显式关闭，避免模板继承造成保存即拨号；`autoComplete` 默认开启，`autoDelete` 不应自动开启。
- 当前文档企业任务数上限 100；需评估本地历史任务与厂商执行任务的分离和容量，不能直接采用自动删除历史的默认实现建议。
- 高级重呼条件需要开启号码状态识别，间隔可基于首呼或上次呼叫；必须保持当前需求的触发条件与时间口径。

以上均来自任务创建/导入正文。[S05][S06] 暂停和结束接口未说明在途通话如何处理，不能推断其必然满足“不打断当前通话”。`pauseDuration` 的单位/行为也未充分说明。[S07][S22]

### 4.4 名单和结果必须以本平台来源为准

厂商导入默认 `isRepeat=1`（任务内排重），当前需求允许跨批次同号独立存在；直接使用默认值可能少导名单。候选方案为平台先按既定规则校验，再结合厂商批次映射选择批次去重或不重复去重；对请求重试另做幂等保护。[S06]

平台至少保留：租户、实例、批次 ID、批次客户 ID、业务类型/编码、任务 ID、呼叫尝试 ID 与厂商通话 ID 映射。`requestUniqueId` 是关联字段，文档没有承诺重复请求自动去重；不能因传了该值就安全重拨。[S04]

名单 `property`、任务 `userFields`、SDK `callVariables`、话单 `userField` 是不同对象，不可只改字段名就认为贯通。须验证同号跨批次、首次/重呼、失败回调、IVR 转人工都能回到原客户行。[S04—S06][S12][S13]

### 4.5 同名字段在不同话单里含义不同

| 字段 | 人工/预览外呼记录 | 预测外呼记录 | 平台处理 |
|---|---|---|---|
| upTime | 坐席接起时间 | 客户接听时间 | 分类型映射客户与坐席时间 |
| bridgeTime | 客户接听时间 | 坐席接听时间 | 不用一份通用映射解释所有外呼 |
| 接听状态 | 1客户未接、2坐席未接、3客户接听、4坐席接听 | 40客户未接、41客户接听、42坐席未接、43双方接听 | 客户接通、双方人工接通分别统计 |

来源：[外呼记录][S12]、[预测外呼记录][S13]。呼入还区分系统应答与人工接听。[S23]

新话单提供客户/双方时长、重呼轮次、最终呼叫标记等有用字段，但不能省略本平台“未知/待确认”状态、重复乱序归并和迟到校准。预测话单有呼叫结果异步更新标记，最终可见时延仍需样本确认。

明细查询单次开始时间范围不超过一个月，普通分页有 10 万条边界，可使用滚动查询。六类报表应从平台归一后的完整明细产生，跨月拆窗并去重，不直接把供应商聚合指标当作本平台指标。[S12][S13][S23]

### 4.6 录音与转写有基础，时间轴仍未验证

录音通过文件名换取试听/下载地址，文档默认 120 分钟过期且可配置；分线录音取决于开通条件，WAV 模式下支持指定客户/坐席侧。[S11]

ASR 查询支持主通道 ID、通话类型、混音/分轨、片段 beginTime/endTime 和 side，处理中返回 -2；可支撑当前文本搜索与定位。[S15] 但本次读取页面未充分明确片段时间单位、与实际音频起点偏移、多文件衔接及所有业务类型覆盖，不能由样例数值猜成毫秒后直接联动播放器。

坐席 `isAsr` 默认不开启，而 SDK 单次呼叫 `cdrIsAsr` 默认开启，两者的优先级和企业开通条件需确认。[S17][S04] ASR 的技术条件不扩大为质检管理需求；现有媒体 POC 不自动关闭。

### 4.7 呼入与资源隔离证据仍不足

IVR 导入目前是厂商导出文件格式，并非已证实可以由本平台规则直接生成的开放流程 JSON；文档定义是 `/ivrProfile/import`，示例却写 `/ivrProfile/export`，存在需要澄清的内部冲突。[S20]

`ivrFlow/query` 是按某次通话查询 IVR 轨迹，不是“查询已发布可选流程列表”。[S21] 仍缺共享号码绑定入口、唯一租户锁定、队列路由、兜底、发布/回滚及启停原子性的完整证据。不能因为来电话单能显示“队列溢出”，就判断兜底业务已经实现。

技能更新为全量替换，而且成功响应示例仍可能带 `failCno`；应核对逐坐席失败，不把顶层成功当全部成功。技能等级数值越小越高，现有 1—10 业务等级须对照原优先级语义及新平台接受范围，不能直接原值透传。[S08]

## 5. 迁移前需要验证的最小闭环

| 编号 | 测试重点 | 通过标准 |
|---|---|---|
| POC-A | 两租户共享企业或实例的隔离 | 无法登录/使用对方坐席、号码、技能；事件、话单、录音和报表均不串租户；共享呼入先锁定租户 |
| POC-B | 本人软电话与安全停用 | 过期令牌可恢复，多标签/多设备策略明确；通话及话后不能被切租户或停用打断；不再接收新任务 |
| POC-C | 两任务竞争同一坐席/外呼组 | 启动前可识别冲突，厂商拒绝不伪造启动成功；小坐席量配置有效 |
| POC-D | 两批同号及来源回传 | 三类编码和客户行分别保留；重试不重复导入/拨号；每次尝试与最终结果精确回原行 |
| POC-E | 客户未接、仅客户接、双方接、乱序/断流 | 客户接通与人工接通分开；离线期间可回补；不会把未知算未接通或自动重拨；报表一致 |
| POC-F | 纯 IVR、转人工、呼入排队及异常 | 零在线坐席的纯 IVR 按预期执行；节点、按键、终态可回查；共享号码异常不路由其他租户 |
| POC-G | 录音/文本独立及时间轴 | 缺失、处理中、过期各自展示；刷新 URL 后可播；角色、单位和时间偏移核对正确 |
| POC-H | 任务控制及长期暂停 | 暂停/终止只停止新拨号；在途继续归档；自动结束配置与本地状态一致；删除不丢来源 |

还需部署方提供：实际产品/区域/版本，`/interface/v10` 与 `/cc` 的鉴权及错误协议；租户模型和资源隔离说明；测试企业/坐席/线路；推送验签、应答、重试上限、断线补偿与话单可见时延；ASR/录音开通条件；各接口限流和容量。

这些是接口验证条件，不构成授权开通付费服务或真实拨号。本次未发送资料给供应商。

## 6. 对现有项目的影响与处置建议

| 层次 | 可以沿用 | 需要变化 |
|---|---|---|
| 业务与页面 | 双工作台、客户批次/档案、三类编码、任务入口、媒体与六类报表 | 增加真实资源冲突、限额、厂商暂停/结束原因的反馈；具体变更先走差异确认 |
| 平台服务 | 租户权限、账号坐席关系、分配与话后、归一模型、统计定义 | 新供应商身份/资源映射、任务适配、事件消费、话单补偿、媒体代理 |
| 前端呼叫 | 联系弹窗和业务操作结构 | CCC Core SDK 生命周期替换为 CTILink；状态、令牌、静音/挂断及退出适配 |
| 数据与历史 | 本地业务 ID、来源快照和历史归属 | 厂商主/子通话 ID、请求 ID、任务/批次 ID 与旧记录并存；历史媒体保持原来源 |
| 原智能外呼 | 现有机器人链路、套餐/分钟账本、原报表 | 本次不自动迁移 |

建议先完成 POC-A、D、E、F 四项决定性验证，再确定是否全面迁移；人工最小呼叫链可作为并行的技术验证范围，但不能据此替代自动任务与呼入验收。当前无法从文档负责任地给出确定人天或报价。

原 ISSUE-218（结果闭环）、ISSUE-220（媒体/文本）继续开放；ISSUE-219 / CS-AUDIT-003 是现有原型一致性缺陷，不归因于 AliCti，也不计作新接口差异。本报告为新增独立评估，不把旧 G2 批准扩展成对 AliCti 的批准，不改原型或旧冻结包。
