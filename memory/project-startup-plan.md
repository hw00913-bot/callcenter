## 范围与页面原则

沿用平台登录、租户/角色、双工作台、坐席/技能、线路号码、三类客户导入、分配与手机号档案、人工外呼、预外呼、IVR、呼入、结果、录音文本及六类云域报表。既有智能外呼域、计费和原报表保留原链路。

默认沿用菜单、布局、表格、筛选、详情、联系客户弹窗及视觉组件。enterpriseId 替换资源映射，不要求把技术参数暴露给普通业务使用者；原品牌/客户上下文可保留。

只在新接口影响用户操作结果时调整：任务资源冲突、号码/坐席资格、暂停自动结束、媒体未就绪和接口失败等提示、状态与禁用条件。每项页面变化须说明原行为、新约束、最小修改与证据，不能为了适配增加无依据功能。

## 可复用与必须适配

| 部分 | 处理方向 |
|---|---|

## 核心流程及图集

业务流程保持已确认用户目标，按新资源和接口边界核对 6 条跨场景流程、26 个场景，不为供应商扩展能力新增场景。

重点链路：

1. 平台登录/选租户 → 供应商账号映射 → 本人坐席资格检查 → 电话服务上线。
2. 业务类型导入 → 校验/去重 → 客户分配 → 人工或自动任务执行。
3. 人工联系 → 客户/坐席状态分别归一 → 结束 → 话后处理 → 原客户归档。
4. 预测/IVR 创建 → 名单及执行资源 → 启动检查 → 暂停/继续/终止 → 异步结果。
5. 共享号码呼入 → 唯一租户确定 → IVR/技能队列 → 人工或兜底。
6. 事件接收 → 话单回查校准 → 录音/文本独立就绪 → 工作台/档案/六报表。

流程图表达参与方职责、判断、异常和跨租户边界；时序图表达平台前端、后端、AliCti API、CTILink/媒体、推送与话单的真实先后。不能将旧图中的 CCC 名称改成 AliCti 就交付。

上游流程/泳道按技能使用本地 PlantUML，时序使用原生 SVG，输出可离线阅读 HTML；图集桌面宽屏、可缩放、可全屏，与原型组成三项主要阅读入口。页面结构材料沿用和核对既有结构，作为分析支撑，不新增产品页面。

## 验收方向

1. 原底座运行文件不变，新目录独立运行；同一浏览器访问两版，数据与坐席锁不相互影响。

3. 26 场景与新接口边界逐项可追溯；原型行为、流程图与时序图相互一致。
4. 验证两任务竞争坐席、跨批次同号、创建不拨号、客户与坐席接听分离、录音文本未就绪等关键演示分支。
