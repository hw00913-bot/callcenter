## 本轮最高优先级（P0）

三项并列最高优先级，先安排方案确认、开发与验收。按依赖推进，不把P0理解为已实现或门禁豁免。

| 优先级 | 范围 | 必须交付的行为 |
| --- | --- | --- |
| P0 | 应用接入 | 应用列表、新增、详情、修改、删除，应用与租户多对多关联、密钥与指定租户身份获取、每个应用回调地址保存。 |
| P0 | 导入客户接口 | DCC、天网等应用接口导入共用能力；明确外呼方式。预外呼必传原供应商任务ID taskId并核归属，按任务坐席组；人工外呼指定有效坐席工号agentWorkNo进入待联系。校验回调配置、逐行结果、请求去重及身份隔离。 新API导入请求必带业务批次号，同app/tenant可多次导入复用；与requestId去重、平台主子批和供应商fileId分离。 六个选填客户资料字段逐行保存，不删除leadCode/phone/priority，业务接口展开字段清单。 请求级businessType必填且按验真租户启用码校验，逐条保存，幂等含类型。 |
| P0 | 外呼未接通填单 | 人工拨号后、预外呼坐席振铃时即可填写原跟进表单；未接通结束保留内容并选择通话状态保存。号码状态沿API-327完整20描述/16编码，712拒接；人工状态与线路结果分别保存。 通话结束且处理结果为已完成沟通并可靠保存后，将本次通话和本次已保存业务信息快照回调原业务系统，携原业务批次号。 已填选填业务字段及选项的业务编码一并快照回传，不只传显示名称。 原导入意向门店/车系编码与名称、Smartcode及留资时间在现有表单和详情显示，完成快照携本次来源原值。 适用每次结果/进度及完成沟通回调携原业务类型码。 |

**实施顺序**

1. 应用接入与租户身份/回调配置先提供接口导入前提；同一P0内可并行开发工作台填单。
2. 分别验收预外呼taskId路由和人工agentWorkNo分配，再串联已约定的结果回调。
3. 联验未接通选择状态、保存/恢复与继续跟进依赖；正式实施和上线前仍按原证据要求核验。
4. 按原app/tenant/record/call固化完成沟通快照，再独立交付与确认；验证批次可复用、重传不重复、保存失败不发、跨应用不串及晚到话单版本方案。

其他v1.1.0功能保留原范围和原优先级；本轮不删除、延期或统一改为P1。混合功能/验收仅指定的接口或填单部分升P0。

## 本版约定

- 导入接口请求级必填businessType（业务类型编码），一次一种，取已验真租户当前启用类型；缺失/无效/停用的新请求拒收。逐条保存原码，名单/详情展示原名称并保编码，坐席按原类型表单跟进，回调携原码。同requestId改类型冲突，已受理同内容技术重放不新增，后续停用不改历史；不同类型分次请求可复用businessBatchNo。原手工CSV不增加逐行必填。
- 应用回调地址已补到新增／修改和详情，列表显示配置状态；本地保存与缺地址导入阻断已局部验证，真实回调仍待实现。
- 每条线索新增选填的意向门店编码、意向门店名称、意向车系编码、意向车系、Smartcode及留资时间；原值显示在既有预览、客户/通话详情和早填单。留资时间来自业务方，不默认平台导入时间。
- 新接口导入请求带业务批次号（建议字段businessBatchNo），同应用/租户可复用；每条记录保存原值并在每次回调带回，requestId继续单独防重。该字段不增加到原手工CSV必填列。
- 通话结束且处理结果为“已完成沟通”并保存成功后，新增完成沟通回调：包含本次通话记录、本次保存的客户业务信息和原业务批次号。已填选填字段及其选项的业务编码也必须回传，多选保留所有选中编码。每次结果/进度回调仍保留；回调失败只补送，不重新拨号。
- 应用与租户多对多，业务系统分别配置应用凭据及回调地址。建议取身份时显式指定租户、校验关联并绑定token；正式报文待审。
- 导入指定预外呼或人工外呼。预外呼仍按任务坐席组分配；人工外呼指定有效坐席工号，进入该坐席待联系，不能套用预测任务和批次。
- 所有接入应用都回调原业务系统，未配置回调地址先拒绝导入。无应用来源的手工界面导入保持平台内处理。
- 人工拨号后、预外呼坐席振铃时可填跟进草稿，原型已局部验证；未接通通话状态选择、条件必填与独立保存现已局部核验，712为拒接，同码不同描述分别保留；人工记录不覆盖客观通话结果。
- 继续跟进在成功保存后保留待联系。预外呼转由当前坐席后续人工跟进；供应商自动重呼排他尚待验证，不能仅凭待联系列表就声称可以安全再次拨号。
- 预测范围继续沿用三类失败确认后120秒自动补提交、八类人工补提交，共享首次之外2次；未知不盲发，秒挂不重呼。

## 实现及验证范围

沿用19个FUNC、22个BR、5个PAGE及14个API历史编号，并按当前需求形成讨论投影；旧编号对应的正式下游分析未重验。本稿另列人工分配、坐席跟进、完成沟通回调三个草案操作和既有工作台草稿页面。14行接口台账、8组源操作不代表14个已经确定并联调的HTTP端点。

原型中直接导入、统一任务操作、回传详情内嵌、通话入口合并以及拨号即填单属于已有局部修复。沿用此前28组定点回归及浏览器未接状态选择/保存/恢复证据；表单阶段切换保留草稿，结束后保存。六项来源资料已做局部合成展示并记录21组定点检查；新增业务批次号和完成沟通回调尚未实现；多对多身份、双方式接口、全部应用回调及预测转人工归属仍待实现；后端与完整表单契约仍待验证。本次businessType在现有预外呼本地合成接收和原界面完成41组定点源码回归、5项语法及名单/详情浏览器核验；完整人工导入接口与真实回调未实现。当前104条CHECK为验收计划，未执行整版测试；见[核验说明](validation-report.md)。

未决保留13项高、9项中、1项低。用户已批准分阶段验收：先审本方工程设计，实现证据开发后、上线前补齐；供应商关键规则、业务系统正式契约及下载可行性仍须先核实。完整责任与依赖见[待核清单](open-items.md)。
