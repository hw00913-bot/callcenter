## 本次可执行产品口径

- 业务系统向平台的 API-001／DCC-RST-IMPORT 增加请求级必填 businessType；一次新请求只允许一种业务类型，取已验真 token 租户配置中当前启用的稳定业务类型编码。业务名称仅展示，不作为协议编码；不由 source、callMode、手机号或任务默认值推导。不新增业务类型管理能力。
- 不同类型分次提交，可以重复使用 businessBatchNo。原 leadCode、phone、priority 必填，预外呼 taskId 与人工坐席的既有分支继续；原业务分组、同线索固定手机号及失败共享额外2次的计数作用域不增加 businessType，也不因另换类型重置。
- 鉴权、租户和应用有效性仍先验真。新业务缺失、无效、未属于当前租户或已停用的类型明确拒收，不产生客户/分配/供应商提交。完整幂等内容包含 businessType；同 app+tenant+requestId 改类型视为冲突。同内容技术重放返回原受理回执，不重复导入，不因后来类型停用而改写历史或重新解释已受理请求；不豁免当前身份安全校验。
- 原类型编码及名称快照逐条存入准确 app/tenant/request行/record，在客户名单、客户详情、通话详情和拨号/振铃早填表单展示。填单使用原类型的业务表单，接口来源记录不允许静默切换类型；后续配置改名/停用不把旧记录改为另一类型，历史缺值显示未提供而不批量猜补。原表单暂不可用时说明原因并保留草稿，不能偷偷选其他表单。
- 每次准确结果/进度及已完成沟通快照回调都携本记录原 businessType 稳定编码，依准确原app/tenant/record/call交付；businessBatchNo、线索编码、六项来源信息及本次已填业务字段/选项编码继续。补送沿原快照，不取最近同号或当前配置覆盖原类型。
- 原手工导入已经有业务类型，保留该流程、单一线索编码、选填后置和既有弹窗；API-002 AliCti 导入报文不新增未证实字段。前端合成实现不证明真实API、回调、租户配置权威接口、版本迁移或并发持久性。
