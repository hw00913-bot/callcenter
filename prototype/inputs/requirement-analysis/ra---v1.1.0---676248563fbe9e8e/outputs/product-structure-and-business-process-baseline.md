## 3. 角色与系统边界

### 角色

- **超管**：应用管理仅超管；租户管理员菜单/页面/管理接口拒绝，不实际改变账号权限
- **运营人员**：按既有权限导入、查看及下载失败明细；不授予应用管理权

### 系统

- **DCC**：DCC决定新业务请求/各行本次priority，新请求级requestId可多行，可选逐行Boolean isNewBatch missing=false；同tenant/原supplierTaskId/leadCode固定phone，true独立主、false/缺省最近已保存主下新子、无主自动首主，不必传previous。接收逐行request/定位/batch/root及精确每次结果；真实计次和精准删除职责不变，技术重传原逐行映射。
- **云呼叫中心**：接口先鉴权/归一完整有效请求幂等，仅新ID固定phone归组并新record/batch；true独立主、false/缺省最近已保存同组主下新子、无主首主，主按本地稳定创建顺序，root保存返回不虚构parent。fileId/实际batch/call事件精准匹配，后有新主不改旧请求/结果root；手工原输入最终priority独立拆批，无新DCCflag/request/归组协议，两来源无每日查询衰减、原时间审计。
- **AliCti供应商**：供应商任务、号码导入、实际调度/主叫选择与结果；真实能力待核

## 4. 产品能力结构

- **系统设置/应用接入管理**：系统设置应用接入，超管可分别列表/新增/详情/修改/删除；日常页简化为生成密钥用于token，保留名称/可访问业务租户和必要不可用演示提示。原保存复用修改，合成凭证不能用于真实服务，生产契约待核。
- **预外呼任务/记录页**：预外呼任务级记录页及常驻导入客户入口；按锁来源进入DCC合成接收或既有手工导入，不可导入禁用并给原因。历史仅未启动补导保留原名单/批次，不扩旧启动策略；当前文本/预览、删除反馈与可信call/SIP精准归属纳入回归判据。

## 6. 业务流程

### FLOW-001 · 导入、结果分流与主子批闭环

关联场景：SC-001、SC-002、SC-003、SC-004、SC-005

可视化：[在 HTML 图集中查看 FLOW-001](business-scenario-atlas.html#FLOW-001)

1. SC-005超管在应用接入独立建立或维护应用凭证：列表/详情/新增/修改/删除各可单独发起，普通修改保留密钥，精确删除不删业务记录。有效应用及授权租户范围作为DCC鉴权前置；日常页简化用途，原型只合成，真实凭证与token失效待核。
2. 任务创建提交锁定接口/手工来源，校验tenant/原supplierTaskId，应用仅鉴权追踪
3. 手工原输入/提交前统一逐条最终priority校验，有效行独立记录单号批次自动提交，不新增DCCflag/request/归组主子协议，无每日衰减；预外呼入口常驻、不可导入保留禁用原因，手工CSV当前文本/有效预览必须一致，新文本或失败预览不提交旧稿，历史补导不扩已启动规则
4. DCC请求级requestId可多行，新业务新ID，各行定位/leadCode/phone/本次priority/可选Boolean isNewBatch，missing=false归一
5. DCC鉴权及归属后先核requestId完整有效内容：同ID同内容返原逐行record/batch/root，不重拆交；异内容拒整重复，后来新主不改旧root
6. 仅新ID逐行固定phone组校验：tenant/原supplierTaskId/leadCode，改号/归属冲突/历史组主不明不提交、多lead同号未决不自动放开，其他有效行继续；不要求DCC previous、不盲配最近同号
7. 每有效新行新record/batch，true新主root=batch；false/缺省有主新子挂按本地主批稳定创建順序最近已保存同组主、无主自动首主，不挂上一子/不虚构parent。保存回执request/行/组/batch/root，本次priority/FIFO提交，未知不重交
8. 53分片以核实enterprise→tenant/原task/fileId/原始号码精确回查实际记录与保存root，接口回传手工查看，不计实际呼叫不推定全导入终态
9. 每次话单事件以实际批次/原始号码/callID或稳定事件精确关联，leadCode仅组不替代匹配；无话单失败独立、秒挂真实条件、重复晚更新不制造新呼叫
10. 接口每次结果携保存request/行/组/实际batch/root/call事件回传固定DCC地址，后有新主不改旧root；手工仅查看，失败补送不重导；未可信纯SIP独立待核、不污染已确认call或阻挡其后可信精准更新，真实非SIP矛盾仍待核
11. DCC决定业务重导/priority/计数，新主子不重置计次；无平台每日查询/衰减/存量改写/重导计划。删除仅实际供应商批次，必要幂等/组/root/映射保留，原时间审计；同号重导排重执行中并行仍partial，不新增先删/等finishRetryFlag；切换精确删除目标/样例清旧反馈，不改旧对象证据

### FLOW-002 · 失败导出与业务记录保护

关联场景：SC-001

可视化：[在 HTML 图集中查看 FLOW-002](business-scenario-atlas.html#FLOW-002)

1. 本地校验失败、供应商同步/异步导入失败分类进入既有失败下载入口；呼叫失败独立记录
2. 按已知失败分片展示收齐或不完整/待核，不推定整个导入终态
3. 生成本次失败快照和导出文件；点击/生成不等成功下载
4. 可信成功下载只清本次快照明细和文件；中断/失败保留
5. 两来源保留必要记录/事件去重/分片交付状态；接口另保原逐行requestId幂等结果/固定phone组/主子root/精准供应商通话映射。后到新失败下次下载，已导出重复不再生，手工不新增DCCflag/request/归组协议。

## 8. 核心状态模型

### 导入业务记录

状态：本地校验失败、本地保存、供应商导入待提交、供应商同步数量与准确成功证据、供应商导入失败（同步/53）、供应商结果未知/待核、供应商已删除（本地保留）、DCC接口分组号码/归属或主批关系待核、DCC接口requestId内容冲突拒绝

转换：DCC鉴权与tenant/原任务归属 → missing flag=false归一 → requestId核完整有效内容；同ID同内容原逐行record/batch/root不重拆交，后来新主不改原root、DCC同ID异归一完整有效内容 → 内容冲突拒整重复请求、不覆盖原结果、DCC仅新ID逐行固定phone组：改号/归属冲突/历史组主不明不提交，多lead同号未决不放开，其他有效行继续、DCC有效新行新record/batch：true独立主root=batch，false/缺省有主新子按本地主批稳定创建顺序挂最近已保存同组主，无主首主；保存root不虚构parent → 本次priority高先/同级FIFO自动提交，已提交不重排/未知不重交、手工原输入/最终priority → 既有逐行校验 → 独立记录单号批次自动提交，无新DCCflag/request/归组主子协议或日龄衰减、准确同步成功证据正常记录，仅汇总不任指行/未知待核；真实同号重导排重执行中并行仍partial、53失败以核实enterprise/tenant/原task/fileId/原始号码精确映射实际record/batch/root → 导出或按来源回传查看，不计实际呼叫、可信下载只清快照明细文件，去重分片交付状态保留；接口原逐行幂等/组/root/供应商通话映射保留，后到新失败下次下载、精准删除明确成功只该实际供应商批次已删，必要本地记录/组/root/幂等/实际映射留存，不作用同组其他主子，不改priority策略、手工当前文本改变或预览失败 → 旧草稿不可提交；重新有效预览后才可按最终priority提交，无旧名单误写

### 每次结果与回传记录

状态：结果已关联、结果待核、接口回传待发送、回传成功、回传失败待补送、手工仅平台查看

转换：接口每次结果/晚更新经精确fileId/实际批次/原始号码/callID或稳定事件回查保存record，取该request/行/组/batch/root回传，后有新主不改旧root，leadCode仅组不替代匹配；手工沿原记录/独立批次/通话事件仅查看，无DCC协议新增。、重复/晚更新不新呼叫，失败补送不改业务结果/重导，不虚构子挂子parent关系。、未可信纯SIP → 独立来源待核证据，不污染原call非SIP结果；随后精准可信call/SIP且无其他真矛盾 → 更新同一call/交付版本，不新增呼叫

### 应用接入配置结果

状态：应用尚未保存、应用已保存、应用已删除

转换：超管列表/详情只读，不改变配置、超管新增有效保存 → 新应用及不可用合成appId/密钥；取消/失败不形成已保存应用、超管修改有效保存 → 名称/租户授权更新、appId/密钥保持；取消/失败原配置不变、超管确认精确删除且保存成功 → 该应用消失/合成身份失效，其他应用/业务任务记录保留；取消/失败不先撤权、非超管管理请求 → 拒绝且配置不变；租户业务身份不升级管理权

## 9. 假设与约束

- P1仅分析排序，不是实施先后
- SRC-083确认取消每日状态查询、自然日priority衰减与存量priority改写；原导入时间仅审计，本次DCC priority直接保存透传，手工提交前最终priority保持。
- DCC管理业务导入、重导及计数，平台不建预算/计时器；供应商内部尝试完整性及SIP晚更新仍交开发核实。
- 工作时间边界（SRC-078/079，SRC-083修订）：按本次最终priority同任务高先/同级FIFO，已提交不撤回、未知不重交；不因时段到来提权或按日期降级。低priority不是禁止呼叫，供应商时段与禁呼配置证据仍待核。
- 仅DCC接口SRC-084～086：tenant/原supplierTaskId/leadCode固定phone组，逐行可选Boolean isNewBatch missing=false；true独立主，false/缺省有主新子挂按本地主批稳定创建顺序最近已保存同组主、无主自动首主。无需DCC previous，不挂上一子/虚构parent，不按最近同号/结果时间/priority选主。先鉴权/归一完整请求幂等，旧请求返原record/batch/root不随新主变动；手工无新flag/request/归组协议。真实规范化/技术作用域/行定位/稳定创建顺序/原子性/持久化/ACK/供应商排重执行中并行开发待核，不称verified。
- 同组仅已绑定phone，改号/归属冲突/历史组主不明拒绝或待核不提交，tenant/原任务隔离；多lead同phone未决不放开，主子不改DCC计次。精准vendorfileId/实际batch/call事件仍必需，leadCode单键/最近主不能替代；供应商同号重导排重执行中并行仍partial，DCC决策，不新增先删/等finishRetryFlag策略。
- 本期原型只用合成应用、不可用于真实服务的演示appSecret与不可用租户身份。生产凭证算法/安全存储、应用管理API、token时效及删除/授权变更后真实token失效机制尚missing/partial，不能从本地CRUD实测提升verified；不新增收费、启停、密钥重置或权限授予操作。演示名称60字/唯一性、分页大小等实现选择未被提升为冻结业务规则。
- SRC-088要求先回归需求与原型对齐再进入下一阶段；本临时事实修订不创建G3、02业务/运营审批或05开发事实。已有候选回归是本地合成观察，生产供应商/认证/CRUD接口缺口维持原状态。
