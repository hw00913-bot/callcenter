# 业务规则

> 来源：冻结需求分析基线 `ra-云呼叫中心-v1.1.0-原始需求重新分析草稿-676248563fbe9e8e`。下列业务规则为只读事实。

## Rules

| Rule ID | Name | Statement | Scenario IDs |
| --- | --- | --- | --- |
| BR-001 | 租户接入 | 应用凭证+tenantId换取租户token；业务请求由token识别租户，任务归租户；应用只留来源追踪，凭据时效与真实接口未定。 超管可独立建立/维护应用用于该用途，日常应用页只表达密钥获取token；普通修改保留appId/密钥，删除使该应用不再获取新身份，合成已发身份失效，业务任务/记录及来源审计保留。生产密钥算法/存储/管理API/token时效和已发真实token失效机制仍未核验。 | ["SC-001", "SC-005"] |
| BR-002 | 逐行单号拆批 | 有效新业务逐行新record和单手机号batch，不覆盖旧记录。DCC请求级requestId可多行，真重导用新ID；逐行isNewBatch可选Boolean、missing=false，同组固定phone保存root；true新主，false/缺省有主新子挂最近已保存同组主、无主auto首主，复用主关联仍新业务编号。同ID同归一完整有效内容返原逐行结果不新建重交，异内容拒整个重复请求；新请求失败行不回滚有效行。手工按原字段/提交前最终priority独立拆批，不新增DCCflag/request/归组协议。 | ["SC-001"] |
| BR-003 | 必填字段与独立优先级 | 接口与手工R可选来源元数据，无字典维护/范围校验；缺R不失败，提供则保留且不删除旧值。priority独立必填，不补默认、不由R推导；taskId为供应商任务。接口按本次DCC提供的有效priority保存与透传，不继承旧priority、不按日期衰减；手工沿提交前逐条最终值。生产类型/长度/数值范围仍由开发核实。 DCC接口每行可选Boolean isNewBatch，未传等同false且归一参与完整有效请求幂等比较，非Boolean不当false；手工不新增该字段。 | ["SC-001"] |
| BR-004 | 自动提交与明确拒绝 | DCC鉴权及租户/原任务归属后，以missing isNewBatch=false归一后的完整有效请求核对requestId；同ID同内容返原逐行record/batch/root，不重拆重交，异内容拒整个重复请求。仅新ID逐行校验固定phone组和主子规则，改号/归属冲突/历史组或主不明不提交，其他有效行继续；旧请求重传不因后有新主重新选root。手工原校验/最终priority保存独立记录批次，不新增DCC接口协议。有效新业务保存后自动提交供应商，明确拒绝失败导出且保留，未知不当拒绝、不自动重交，已提交不撤回重排。 | ["SC-001"] |
| BR-005 | 失败导出生命周期 | 接口和手工导入失败均适用：未成功下载不固定到期；成功下载后只删除本次导出明细/文件，失败中断保留，成功业务记录不受影响；真实下载成功信号待核。 | ["SC-001"] |
| BR-006 | 取消平台每日跟进与衰减边界 | 平台取消每日状态查询、自然日priority衰减及派生存量改写，仅服务衰减的获取退出且不改独立人工查询。本次priority不因未拨/未接通/跨日/原导入日/旧批值改变，原时间审计，DCC决定本次导入及priority；同组主子不恢复每日策略。手工保留提交前最终priority和独立拆批，不新增DCCflag/request/归组主子协议。 | ["SC-001"] |
| BR-007 | 定向删除保留本地 | 删除仅指定原任务具体供应商批次号码，明确成功后本地记录、必要幂等/固定phone组/主子root/精确供应商通话映射保留并回传状态；失败未知不标已删。不按leadCode/主批/组整体删除，不作用其他主子或同号记录。无每日衰减/平台重导计划，执行中并发精准删除仍待核。 切换删除目标或结果样例清旧反馈，不抹对应旧对象已保存证据、不把旧反馈当当前结果。 | ["SC-001", "SC-002", "SC-004"] |
| BR-008 | 线路侧结果回传 | 关联线路侧风控的每次话单/SIP及结果；接口任务回传DCC，由DCC决定是否再次导入。供应商导航可能自动降级，不承诺绝对换主叫，不叠加平台重导。 未可信纯SIP单独保留待核来源，不改原call业务结果或冒充可信非SIP冲突；无其他真实矛盾时，随后可信精准call/SIP在同一对象正常更新，无新增实际呼叫。 | ["SC-002"] |
| BR-009 | 无话单失败回传 | 可信且准确关联的预测呼叫失败事件回传原因，无话单失败不等待客户状态推送/话单；精确事件编号与原因映射待核。；禁呼未解禁、限呼未到期及无可用中继失败回传真实原因，由DCC判断恢复条件与重导，不绕过限制、不在平台设置自动恢复或重导预算。 | ["SC-003"] |
| BR-010 | 秒挂判定 | 确认客户已接听、客户挂断且真实时长0～2秒（含0/2），纳入秒挂；未接通/缺失/异常不纳。供应商枚举和字段单位待核。 | ["SC-004"] |
| BR-011 | 秒挂识别结果职责 | 秒挂是否/何时重导及次数由DCC决策，原30分钟业务上下文不形成平台计时器；不再发放独立额外4次。 | ["SC-004"] |
| BR-012 | 线索归组与主子批次追溯 | 仅DCC接口按tenant/原supplierTaskId/leadCode固定phone归组，首次有效绑定phone，后续仅同phone；跨tenant/原任务隔离，不混组。新业务请求新requestId，可多行，每有效新行新recordId和单手机号batchId；逐行可选Boolean isNewBatch、missing=false，true可同组另开独立主(root=batch)，false/缺省有主新子root=最近已保存同组主batch，无主自动首主(root=batch)。最近主按本地主批创建顺序/稳定顺序，不按最近同号/结果时间/priority/子批，子不挂上一子。DCC不必传previousBatchId/parentBatchId且不虚构parent，root必须保存回执。先鉴权/归一后完整请求幂等，同ID同内容优先原逐行结果/映射不新建重交，异内容拒整重复；后来新主不改旧请求root。改号/归属冲突/历史组或主不明拒绝或待核不提交，多lead同phone未决不放开。本次priority不旧继承，原时间审计；每次结果依精确vendorfileId/实际batch/原始号码/call事件而非leadCode单键。DCC计次不因主子改变，手工不新增此接口协议。 | ["SC-002", "SC-004"] |
| BR-013 | DCC统一业务计数 | 三天五呼及重导次数由DCC管理，单任务范围，初呼及秒挂同计5次目标，首次导入当日第1天；普通双方接通停止但秒挂例外。平台不重复调度计数。；初呼与秒挂共用单任务5次目标，由DCC按真实尝试汇总；重新导入请求或重复通知不直接计实际呼叫，平台不新增业务额度。 SRC-084～086仅改归组/主子，新主/子编号不直接算实际呼叫或重置DCC计数，多lead同phone计次关系仍待核。 | ["SC-002", "SC-004"] |
| BR-014 | 手工导入提交前优先级 | 手工必需leadCode与priority，R可选无字典维护/范围校验，一号一独立批次；统一/逐条priority仅提交前可改、最终值保存提交。统一导入客户入口在预外呼列表及任务内常驻；按已锁来源分派DCC或手工入口，DCC任务不能使用手工写入口，后端同时校验来源；不可导入状态保留禁用入口及原因；提交后无人工改priority或自然日衰减。手工不新增DCC requestId/isNewBatch/归组主子字段或校验。 常驻通用导入入口按锁来源打开对应界面，接口任务不开放手工混入；手工CSV变化/预览失败使旧草稿不可提交，提交前复核当前有效预览。 | ["SC-001"] |
| BR-015 | 待核与可靠回传 | 关联不明/超时/冲突待核，不伪造结果终态，重复/SIP晚更新不算新呼叫。DCC新业务逐行固定phone组校验，改号/归属冲突/历史组或主不明拒绝或待核不提交，其他有效行继续，多lead同phone未决不放开，不盲配最近同号。DCC无需previous，不因遗漏上一批次拒绝。请求级幂等优先于新主子分配：missing flag=false归一后同ID同完整有效内容返原record/batch/root，异内容拒整个重复请求。补送不重导；真实规范化/作用域/原子性和供应商同号重导/排重/执行中并行待核，不新增先删/等finishRetryFlag策略。 未可信SIP来源与真实已确认非SIP矛盾分开；未可信包不污染原call或阻挡随后可信准确更新，真正矛盾继续待核。切换精确删除目标/结果样例清旧反馈且保留原业务证据。 | ["SC-001", "SC-002", "SC-003", "SC-004"] |
| BR-016 | 任务来源锁定 | 创建任务提交后锁定DCC接口导入或手工导入一种来源，不可切换或混用；后端同时校验taskId与方式，任务归租户不绑定应用。 预外呼列表/任务内导入入口常驻并按该锁来源打开；不可导入保留禁用原因，既有历史任务仅未启动补导且原名单批次累计、不扩启动后规则。 | [] |
| BR-017 | 固定回传与最后一通 | 接口任务每次结果向后台配置固定地址回传requestId+行定位、tenant/原supplierTaskId/leadCode/phone、该实际记录batchId/rootBatchId及callID或稳定事件；root从保存映射取、后有新主不改旧归属。leadCode只组归属，供应商fileId/实际批次/call精确匹配保持；手工仅查看不新增DCC协议，无前台/租户接收端设置、不发真实回调。finishRetryFlag严格Integer1/0/未知，独立SIP晚更新，不宣整个任务或DCC计划完成、不新加等待该标记重导策略，每次结果回传非仅最后。 | [] |
| BR-018 | 导入结果证据与失败分片关联 | 同步result=0不等逐条全成功，展示本地校验保存/供应商导入/呼叫阶段及原始importTotal/successTotal/invalidTotal；准确成功证据正常记录，仅汇总不任指行，未知矛盾待核。53分片按enterpriseId经核实tenant/原taskId/精确fileId/原始号码回查实际记录batch及保存组/root，多候选待核，不用leadCode单键/最近同号。totalBatchCount/currentBatchCount仅失败推送分片非业务主子，重复不新增/乱序迟到不丢；收齐仅该声明推送组、不等全导入终态，未收不推定零失败。接口回传原导入失败及requestId+行定位/组/实际batch/root，供应商未给业务字段则精确回查保存映射、不新增供应商协议承诺；手工仅查看。导入失败不计实际呼叫/平台重导，补送不重做供应商导入。 | ["SC-001"] |
| BR-019 | 失败导出快照与必要状态保留 | 失败快照显示分片完整性/待核，可信成功仅清该快照明细文件，失败中断保留、后到新失败下次下载。两来源客户记录、必要事件去重/分片交付状态保留；接口原逐行requestId幂等结果/固定phone组/主子root/精确vendorfileId和实际batch/call映射不随明细清理/精准删除丢失。手工不新增DCCflag/request/归组协议，已导出重复不再生，不清空整个导入或成功客户。 | ["SC-001"] |
| BR-020 | 应用管理超管权限 | 应用接入的列表查询、查看详情、新增、修改、删除是超管可独立发起的五个业务操作；旧配置保存复用修改，不静默重编号。非超管菜单/直达页面/管理调用拒绝且无写，租户业务身份不获管理权，普通运营原导入/下载不移除。新建保存应用名称/可访问业务租户及appId/密钥，普通修改不重置；查看不写、取消/保存失败不假造成功。精确删除只该应用，合成凭证/已发身份失效，其他应用和业务记录/任务/结果保留。日常页简化密钥获取token，移除技术身份交换面板但保留授权验证和不可用合成密钥必要提示。生产凭证/CRUD/token撤权契约仍missing/partial；未要求的收费/启停/密钥重置/权限自动授予不添加。 | ["SC-001", "SC-005"] |
| BR-021 | 待提交记录优先级与FIFO次序 | 同任务待提交按本次有效priority高先、同级本地导入时间FIFO，不同任务独立；DCC本次输入/手工提交前最终值，不按旧批或日期改写。已提交不撤回重排，未知提交不因重排或同requestId重传重复提交；主子选择不改变priority、不承诺拨打顺序。 | ["SC-001"] |
