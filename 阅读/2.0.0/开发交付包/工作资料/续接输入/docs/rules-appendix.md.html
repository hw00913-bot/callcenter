# 当前全局业务约束

GR-IDENTITY：统一账号以准确稳定身份关联已授权租户，五种生产角色与本人坐席能力分离；不按同名／手机号自动合并身份。

GR-SCOPE：每次读取和操作均按当前账号、合法租户、品牌、模块、功能权与对象范围重验；品牌配置关系不授全品牌客户资料。

GR-AUTH：菜单可见、操作资格和数据范围分别判断；总部／门店角色不互相冒用，超管监管不代办业务，未授功能不自动开放。

GR-DATA-FACTS：受理、排队、真实拨打、接通、执行结束、重试收敛、正式内容保存、归档、节点推进、业务结论分别记录；不把前一状态冒充后一状态。

GR-SERIAL：同一业务串行；在途/排队/重试/unknown及事实冲突未可靠收敛不启动新段/新run或完成废弃。正常办理的必要本人内容须正常归档；缺内容仅当前负责租户ADMIN确认无法补填+原因并绑定准确run/段/缺失范围后，可在真实执行收敛时受控废弃结清。结清保缺失/未完成，不伪造archive/completed；后继可识别可靠旧废弃收尾，不要求其变正常archived=true。

GR-CONFIG：TEMPLATE的模板字段参考分类只供编排，实际分类独立关联当前同品牌兼容模板，新run仅消费明确生效配置并封完整方案，已开始run不追改。DIRECT不消费路由或生成run；旧allowDirect标志不自动转换既有业务模式。 当前有出口新配置必须唯一末位ELSE；当前新模板END固定CLOSE；两种原动作仅旧已运行历史按原捕获解释。

GR-FIELDS：字段以品牌、IMPORT/FOLLOWUP用途和稳定ID解释，同名不同用途不合并；类型、选项和取值上下文不相容即拒，不按标签名／首项猜配。 对当前可可靠读取schema内、启用且支持条件的非必填IMPORT字段，新导入/新run准备时缺列规范化为null用于判断；必填缺失或schema读取失败仍拒绝，通话/填写未知及已捕获历史缺失不在读取时补空。

GR-PRIVACY：当前负责方按资格办理；转出方仅见本方截止快照；实际接听人只填自己的准确原段，查询权、核对权、跟进责任均不替代实际填写权。

GR-CONTACT：本租户规范号码按所有有效限制来源独立判定，解除某来源不解除其他来源；呼出准入覆盖四类呼叫，未知不放行，正常呼入不被外呼限制拦。同号正在执行的联系租约、联系间隔和当日频次单独核验；同号多业务不合并身份，有冲突按五档降序、queuedAt/queueSequence入队FIFO及稳定业务ID的统一总序协调；同号与同资源使用同一顺序，旧分类0～999仅保历史和原专业兼容，不参与新执行排序。

GR-UNKNOWN：失败与未知分开；未知保留同次请求身份、输入和待核状态，不重放新请求、不假报成功或以空结果/0值替代读取失败。 未知导入先核对原请求；服务端产出的记录必须按原请求/准确任务/租户/渠道关联，读取故障不解除请求身份，不允许以新请求重试产生重复副作用。基础名称/编码/手机号/优先级按原类型和别名严格校验，旧已捕获请求只读重放不接受客户端伪报。

GR-NO-HISTORY：本轮规划无旧流转数据迁移／模板兼容；未来发生的运行、跟进、通话、来源和审计快照仍按产品规则完整保留。专业现有能力的复用不等于迁移旧流转账本。

GR-LIST-ORDER：普通业务/历史列表按真实更新时间倒序后分页；待执行推荐视图按同资源五档执行优先级及同级入队时间/稳定序号排序。无可靠时间保持稳定，不在读取时造时间。字段／选项顺序、分支优先级、节点及事件序列保业务语义顺序。

GR-HANDLING-MODE：当前由入口决定办理模式：准确AI/预外呼任务入口固定TASK/DIRECT，按任务MANUAL/API渠道导入；业务分类入口固定CATEGORY/TEMPLATE，人工或接口进入当前分类模板。没有中央模式选择、分类允许直接跟进开关或AI第三种FLOW来源，TEMPLATE失败不降级。旧无TASK来源的DIRECT及旧已捕获END来源分别只按原历史合同核验，不补新来源。 当前新建/修改模板的END固定正常结束CLOSE，不提供是否直接跟进配置，当前新导入/路由/重开不得接纳旧DIRECT_FOLLOWUP配置；已运行历史按原捕获方案和原合法来源收尾，不改历史为CLOSE，不借旧END来源授权当前新周期。新TASK/DIRECT始终直接跟进，不显示启用流程；旧无TASK来源DIRECT仅保原合法转换能力。

GR-NAVIGATION：正常跨业务域、切租户及系统退出不因拨号/振铃/通话/话后/电话未知而拦截，也不强制先退出电话；身份、数据范围和普通未保存表单检查保留，撤权后的有限当前收尾是独立机制。 业务分类列表提供导入名单并锁定准确分类；原导入与分配改为导入批次，以批次结果/详情为主。独立业务名单保工作队列、原单条/同组批量手动分配及明确发起；主菜单打开/刷新不带临时批次过滤，准确批次详情和recordId详情各保自身上下文，账号/租户/撤权重新核验。

GR-END-ACTION：当前新建/修改模板的END固定正常结束CLOSE，不提供是否直接跟进配置，当前新导入/路由/重开不得接纳旧DIRECT_FOLLOWUP配置；已运行历史按原捕获方案和原合法来源收尾，不改历史为CLOSE，不借旧END来源授权当前新周期。新TASK/DIRECT始终直接跟进，不显示启用流程；旧无TASK来源DIRECT仅保原合法转换能力。

GR-LOCAL-ROUTE：线索域转交组件允许CURRENT本租户分支；命中后保持owner、run及tenant阶段，不新建跨租户截止/轮次，不清原安排与封存结果，并重核后继CALL资格。OTHER仍执行原意向锚定和跨租户保护；CURRENT不冒充OTHER，拒伪造目标或过期令牌。

GR-CUSTOMER-SIP：流转判断分别使用TIANRUN_MANUAL_SIP_CAUSE和TIANRUN_PREDICTIVE_SIP_CAUSE客户侧结果：200已接通、710～724当前字典；不再用1～4接听标记推断，不改AI状态域或原专业记录的其他状态展示。新回执与实际方式/原段/场景准确关联，未知PENDING。

GR-EXECUTION-ARRANGEMENT：TEMPLATE与DIRECT共用本租户具体任务/坐席与五档执行优先级，模板分租户默认和导入覆盖均按当前实际执行权复核；同资源可办理待办先高后低、同级入队FIFO，不抢占既有执行，手动分配入口保留。 当前排队事实仅属于准确当前run/nodeRun/directCycle及有效资源安排；新运行未安排清当前queue别名，显示未记录，不能借旧运行队列时间或业务createdAt抢队。相同当前运行/资源仅重存或调等级保原FIFO，新运行重新分配同资源才产生新queuedAt/queueSequence。未安排待办排序与队列时间展示分开，按当前节点进入/当前周期开始的可信时间，身份未知保持未知。 导入与明确执行使用相同底层配置语义指纹；已知成功准入包装字段和对象键序不构成业务配置变化。旧schema2 TASK/DIRECT仅在完整准确身份及已知wrapper/basis证明等价时只读兼容；未知附加项或真实映射/来源/模板/状态变化继续拒绝，不回写旧快照，TEMPLATE标签依赖保完整指纹。

GR-ASSIGNMENT-SIMPLIFICATION：人工默认MANUAL人工分配，可无seat先保存/导入待分配，SPECIFIC_SEAT才必选seat；PRED只任务、AI任务+scene，模板/导入/分配无独立责任人。真实人员由坐席分配及实际执行/接听事实记录，历史不迁移，原权限与五档/FIFO/在途继续。

GR-TASK-UNIFIED-IMPORT：任务配置保存准确业务分类；AI从准确场景取得分类和供应商映射，PRED从任务配置取得分类。导入自动带入并锁定，不在导入时临时重选或按名称/首项猜。顶部入口只选择目标任务，随即同窗展示相同导入表。缺失、冲突、失效关联到任务/场景配置维护。MANUAL任务仅手工上传/粘贴，AUTO/API仅只读接收字段与要求；本地静态演示不提供真实接口上传或假造API结果。 先确定实际呼叫方式、条件首路径和必要AI场景，再生成本次schema：系统业务编码/客户称呼/客户号码必需；TEMPLATE保留本次IMPORT条件分流字段，其余只取该scene/platform实际IMPORT_FIELD引用及CUSTOM_COLUMN专属列，未引用的分类额外必填不阻AI导入。非AI仍按实际分类IMPORT。FOLLOWUP不混入；下载CSV/XLSX、列映射、逐行校验、参数生成与规范值/定义快照使用同一准确schema。场景/字段/资料/目标变化失效旧预检。 统一业务及批次保存entrySource.kind=TASK/CATEGORY、importChannel=MANUAL/API、handlingMode及准确分类/租户；TASK的taskImportSource按schema2保存method/taskId/aiSceneId?/categoryId/tenantId/brandId/batchId/importChannel/dataImportSource及targetFingerprint/parameterMappingFingerprint。每行规范业务值与独立供应商customValues/定义/参数快照同次捕获；不把供应商专属值混record.fields，不持久第二份专业业务行，不按手机号认领旧业务或重复供应商导入。 未知导入先核对原请求；服务端产出的记录必须按原请求/准确任务/租户/渠道关联，读取故障不解除请求身份，不允许以新请求重试产生重复副作用。基础名称/编码/手机号/优先级按原类型和别名严格校验，旧已捕获请求只读重放不接受客户端伪报。 当前/旧/generic供应商专属快照与兼容副本只按可信原始任务/批次租户及品牌投影，所有值和配置指纹均受同一范围约束，不泄露给来源方或另一租户；公共业务资料及原截止历史保持。预外呼新安排/执行同核已配置分类和品牌，统一历史未知不在读取时首次补类或换类。

GR-LIFECYCLE-SETTLEMENT：受控缺内容废弃仅当前ownerADMIN确认无法补填+原因/准确范围，真实执行收敛后异常结清，保缺失未完成不假archive；旧弃原人补齐/合法结清不永久卡后继DIRECT。END历史合法与首MANUAL当期例外分开，resume新周期核分类；停止中原受理事实按原ID入账不授新派发或提前解锁。
