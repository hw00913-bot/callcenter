## 当前关键边界

- 当前由入口决定办理模式：准确AI/预外呼任务入口固定TASK/DIRECT，按任务MANUAL/API渠道导入；业务分类入口固定CATEGORY/TEMPLATE，人工或接口进入当前分类模板。没有中央模式选择、分类允许直接跟进开关或AI第三种FLOW来源，TEMPLATE失败不降级。旧无TASK来源的DIRECT及旧已捕获END来源分别只按原历史合同核验，不补新来源。 当前新建/修改模板的END固定正常结束CLOSE，不提供是否直接跟进配置，当前新导入/路由/重开不得接纳旧DIRECT_FOLLOWUP配置；已运行历史按原捕获方案和原合法来源收尾，不改历史为CLOSE，不借旧END来源授权当前新周期。新TASK/DIRECT始终直接跟进，不显示启用流程；旧无TASK来源DIRECT仅保原合法转换能力。
- 人工默认MANUAL人工分配，可无seat先保存/导入待分配，SPECIFIC_SEAT才必选seat；PRED只任务、AI任务+scene，模板/导入/分配无独立责任人。真实人员由坐席分配及实际执行/接听事实记录，历史不迁移，原权限与五档/FIFO/在途继续。
- TEMPLATE与DIRECT共用本租户具体任务/坐席与五档执行优先级，模板分租户默认和导入覆盖均按当前实际执行权复核；同资源可办理待办先高后低、同级入队FIFO，不抢占既有执行，手动分配入口保留。 当前排队事实仅属于准确当前run/nodeRun/directCycle及有效资源安排；新运行未安排清当前queue别名，显示未记录，不能借旧运行队列时间或业务createdAt抢队。相同当前运行/资源仅重存或调等级保原FIFO，新运行重新分配同资源才产生新queuedAt/queueSequence。未安排待办排序与队列时间展示分开，按当前节点进入/当前周期开始的可信时间，身份未知保持未知。 导入与明确执行使用相同底层配置语义指纹；已知成功准入包装字段和对象键序不构成业务配置变化。旧schema2 TASK/DIRECT仅在完整准确身份及已知wrapper/basis证明等价时只读兼容；未知附加项或真实映射/来源/模板/状态变化继续拒绝，不回写旧快照，TEMPLATE标签依赖保完整指纹。 模板AI呼叫节点直接显示AI呼叫任务，任务先于对应场景；候选仍按原实际执行tenant、分类、供应商/平台、任务状态和对象权筛选。选择准确任务后仅唯一明确sceneId或专业任务关联带出场景，多匹配/冲突/缺证不选首项；可明确暂不指定、后续分配，清本租户任务及场景默认并保其他tenant映射，执行前有效具体任务/场景准入不变。 冷打开已选AI的节点或切换AI时，在合法tenant/category和原ADMIN+task.assign资格下每editor/node/tenant/category自动读取一次目录；异步前后重核编辑器、方式、范围与权限，旧回调不落新草稿。失败明确且不因重绘循环，原刷新按钮允许重试；选择方式/任务和目录完成重绘保右侧配置区滚动，异步返回前读取当前草稿，不丢未提交输入。 无执行tenant、范围不一致、无参照分类或无任务安排权时仍显示禁用AI任务入口及准确原因，不把顶部已选tenant误称未切换，不授SUPER或运营新task.assign权。模板品牌配置权不授其他租户私有资源，原人工MANUAL/SPECIFIC_SEAT、PRED仅任务、五档及已捕获运行快照保持。

- 未知导入先核对原请求；服务端产出的记录必须按原请求/准确任务/租户/渠道关联，读取故障不解除请求身份，不允许以新请求重试产生重复副作用。基础名称/编码/手机号/优先级按原类型和别名严格校验，旧已捕获请求只读重放不接受客户端伪报。 当前/旧/generic供应商专属快照与兼容副本只按可信原始任务/批次租户及品牌投影，所有值和配置指纹均受同一范围约束，不泄露给来源方或另一租户；公共业务资料及原截止历史保持。预外呼新安排/执行同核已配置分类和品牌，统一历史未知不在读取时首次补类或换类。
