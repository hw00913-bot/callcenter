# D联络云 v2.0.0 当前产品规格与Mock原型

当前基线：2.0.0-current-20261102-step54。规范化输入和产品规格只投影已确认当前事实；历史来源/冻结计划不并行授权已撤配置，不改变原审批记录。

## 产品目标

43个FUNC、163个AC、43个当前PAGE及222项专业能力保留身份。当前由入口决定办理模式：准确AI/预外呼任务入口固定TASK/DIRECT，按任务MANUAL/API渠道导入；业务分类入口固定CATEGORY/TEMPLATE，人工或接口进入当前分类模板。没有中央模式选择、分类允许直接跟进开关或AI第三种FLOW来源，TEMPLATE失败不降级。旧无TASK来源的DIRECT及旧已捕获END来源分别只按原历史合同核验，不补新来源。 当前新建/修改模板的END固定正常结束CLOSE，不提供是否直接跟进配置，当前新导入/路由/重开不得接纳旧DIRECT_FOLLOWUP配置；已运行历史按原捕获方案和原合法来源收尾，不改历史为CLOSE，不借旧END来源授权当前新周期。新TASK/DIRECT始终直接跟进，不显示启用流程；旧无TASK来源DIRECT仅保原合法转换能力。

## 目标用户

平台超级管理员、租户管理员、运营与有权读取者按当前授权进入；实际拨打/接听填写权与管理/核对资格分开。

## 核心用户路径

当前由入口决定办理模式：准确AI/预外呼任务入口固定TASK/DIRECT，按任务MANUAL/API渠道导入；业务分类入口固定CATEGORY/TEMPLATE，人工或接口进入当前分类模板。没有中央模式选择、分类允许直接跟进开关或AI第三种FLOW来源，TEMPLATE失败不降级。旧无TASK来源的DIRECT及旧已捕获END来源分别只按原历史合同核验，不补新来源。 任务配置保存准确业务分类；AI从准确场景取得分类和供应商映射，PRED从任务配置取得分类。导入自动带入并锁定，不在导入时临时重选或按名称/首项猜。顶部入口只选择目标任务，随即同窗展示相同导入表。缺失、冲突、失效关联到任务/场景配置维护。MANUAL任务仅手工上传/粘贴，AUTO/API仅只读接收字段与要求；本地静态演示不提供真实接口上传或假造API结果。 当前新建/修改模板的END固定正常结束CLOSE，不提供是否直接跟进配置，当前新导入/路由/重开不得接纳旧DIRECT_FOLLOWUP配置；已运行历史按原捕获方案和原合法来源收尾，不改历史为CLOSE，不借旧END来源授权当前新周期。新TASK/DIRECT始终直接跟进，不显示启用流程；旧无TASK来源DIRECT仅保原合法转换能力。
AI/PRED共用轻量导入：文件或粘贴名单→检查及逐行编辑→确认。主区不要求重填场景、分类、批次或优先级；批次默认文件名或任务名+本次窗口时间，选填折叠项可修改，五档默认中。文件读取中禁用旧检查；0有效确认禁用且底部说明/表外行号编码原因可见，编辑后旧结果失效需重检。AI全部行通过才确认；PRED允许当前检查的合法有效子集二次确认。成功行封存不重导，剩余失败草稿可保留/重开/更正后以新请求重检续入，原物理行号与当前编辑行号明确区分，成功后关闭按钮显示关闭。 原专业名单直接在原列表展示：保姓名、电话、批次、原操作与原统计，新业务按准确recordId只读回链；旧原生行缺业务编码/业务分类/五档执行优先级/导入入口四项时直接留空，不单列历史名单、不按手机号补链。统一业务数/办理状态不冒充供应商受理、真实拨打、接通或话单数。
分类路径按实际首组/场景正式预检→CATEGORY/TEMPLATE记录与运行→合法执行安排→明确起呼→实际本人或系统准确归档→有权确认后继/正常END。任务路径自动带入准确任务配置→本次schema检查→TASK/DIRECT账本→明确执行与周期结论。
人工默认MANUAL人工分配，可无seat先保存/导入待分配，SPECIFIC_SEAT才必选seat；PRED只任务、AI任务+scene，模板/导入/分配无独立责任人。真实人员由坐席分配及实际执行/接听事实记录，历史不迁移，原权限与五档/FIFO/在途继续。

账号、租户、品牌、成员授权、IMPORT/FOLLOWUP字段、业务分类、单模板路由、批次、entrySource任务/分类来源及渠道、统一业务记录、DIRECT周期、TEMPLATE运行/节点、准确执行/通话、内容及供应商参数快照、联系限制和审计。旧allowDirect/END来源仅按准确历史合同读取，不成为当前新配置。

## 交付方式

本版静态HTTP/本地查看入口及规范输入用于产品对齐；本次规格组装和发布不修改原型运行代码、不新增清空或迁移、不给予正式业务/运营/工程批准。file方式和真实服务验证保各次未验边界。

## 范围

先确定实际呼叫方式、条件首路径和必要AI场景，再生成本次schema：系统业务编码/客户称呼/客户号码必需；TEMPLATE保留本次IMPORT条件分流字段，其余只取该scene/platform实际IMPORT_FIELD引用及CUSTOM_COLUMN专属列，未引用的分类额外必填不阻AI导入。非AI仍按实际分类IMPORT。FOLLOWUP不混入；下载CSV/XLSX、列映射、逐行校验、参数生成与规范值/定义快照使用同一准确schema。场景/字段/资料/目标变化失效旧预检。
线索域转交组件允许CURRENT本租户分支；命中后保持owner、run及tenant阶段，不新建跨租户截止/轮次，不清原安排与封存结果，并重核后继CALL资格。OTHER仍执行原意向锚定和跨租户保护；CURRENT不冒充OTHER，拒伪造目标或过期令牌。
TEMPLATE与DIRECT共用本租户具体任务/坐席与五档执行优先级，模板分租户默认和导入覆盖均按当前实际执行权复核；同资源可办理待办先高后低、同级入队FIFO，不抢占既有执行，手动分配入口保留。 当前排队事实仅属于准确当前run/nodeRun/directCycle及有效资源安排；新运行未安排清当前queue别名，显示未记录，不能借旧运行队列时间或业务createdAt抢队。相同当前运行/资源仅重存或调等级保原FIFO，新运行重新分配同资源才产生新queuedAt/queueSequence。未安排待办排序与队列时间展示分开，按当前节点进入/当前周期开始的可信时间，身份未知保持未知。 导入与明确执行使用相同底层配置语义指纹；已知成功准入包装字段和对象键序不构成业务配置变化。旧schema2 TASK/DIRECT仅在完整准确身份及已知wrapper/basis证明等价时只读兼容；未知附加项或真实映射/来源/模板/状态变化继续拒绝，不回写旧快照，TEMPLATE标签依赖保完整指纹。
受理、排队、真实拨打、接通、执行结束、重试收敛、正式内容保存、归档、节点推进、业务结论分别记录；不把前一状态冒充后一状态。
当前负责方按资格办理；转出方仅见本方截止快照；实际接听人只填自己的准确原段，查询权、核对权、跟进责任均不替代实际填写权。
受控缺内容废弃仅当前ownerADMIN确认无法补填+原因/准确范围，真实执行收敛后异常结清，保缺失未完成不假archive；旧弃原人补齐/合法结清不永久卡后继DIRECT。END历史合法与首MANUAL当期例外分开，resume新周期核分类；停止中原受理事实按原ID入账不授新派发或提前解锁。

## 非本期范围

通用CRM或统一任务引擎、自动新起呼/推进/转交、跨品牌客户共享、按手机号合并业务、重写已捕获旧周期/快照、真实接口或生产批准。旧无TASK历史的合法转换保持精确旧范围，不授新TASK启用流程。
