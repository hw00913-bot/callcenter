## 3. 角色与系统边界

### 角色

- **超管**：应用管理仅超管；租户管理员菜单/页面/管理接口拒绝，不实际改变账号权限
- **运营人员**：按既有权限导入、查看及下载失败明细；不授予应用管理权

### 系统

- **DCC**：主动传入客户与精准删除请求
- **云呼叫中心**：本地留存、优先级、状态守卫与关联批次
- **AliCti供应商**：供应商任务、号码导入、实际调度/主叫选择与结果；真实能力待核

## 6. 业务流程

### FLOW-001 · 导入、结果分流与原始链闭环

关联场景：SC-001、SC-002、SC-003、SC-004

可视化：[在 HTML 图集中查看 FLOW-001](business-scenario-atlas.html#FLOW-001)

1. 创建任务提交时锁定接口/手工方式，校验tenant/task，应用仅鉴权与追踪
2. 逐行校验并保存单号批次自动提交；同步数量准确记录，result0不等逐条全成功；待提交高优先级先/同级FIFO，已提交不重排，仅同任务，不同任务独立
3. 53失败推送分片回查企业/任务/供应商fileId/原始号码到本地批次和leadCode，重复不新增迟到不丢；接口任务回传导入阶段失败，手工只查看，不计呼叫不自重导
4. 供应商每次事件/话单回查任务批次线索手机号；无话单失败独立保存、秒挂按真实条件识别
5. 接口任务每次结果回传后台固定DCC地址，手工任务仅平台查看；重复/晚更新不制造新呼叫
6. DCC决定是否/何时重新导入；平台不创建重导计划或额度
7. 保留原导入北京时间自然日priority衰减，可信未拨/未接通才降级，精准删除成功停降级

### FLOW-002 · 失败导出与业务记录保护

关联场景：SC-001

可视化：[在 HTML 图集中查看 FLOW-002](business-scenario-atlas.html#FLOW-002)

1. 本地校验失败、供应商同步/异步导入失败分类进入既有失败下载入口；呼叫失败独立记录
2. 按已知失败分片展示收齐或不完整/待核，不推定整个导入终态
3. 生成本次失败快照和导出文件；点击/生成不等成功下载
4. 可信成功下载只清本次快照明细和文件；中断/失败保留
5. 保留必要关联、去重、分片及DCC交付状态；迟到新失败可再次下载，已导出重复不再生成

## 8. 核心状态模型

### 导入业务记录

状态：本地校验失败、本地保存、供应商导入待提交、供应商同步数量与准确成功证据、供应商导入失败（同步/53）、供应商结果未知/待核、供应商已删除（本地保留）

转换：有效行本地保存 → 同任务待提交priority高先/同级FIFO → 自动提交；已提交不重排、同步准确证据正常记录；只汇总不盲指定成功行，未知待核、53异步失败 → 分片关联合并 → 失败导出及按任务来源回传/查看，不计实际呼叫、可信下载成功仅清本次快照明细/文件；保留关联、去重、分片、交付状态，后到新失败待再次下载、精准删除明确成功 → 供应商已删除（本地保留）

### 每次结果与回传记录

状态：结果已关联、结果待核、接口回传待发送、回传成功、回传失败待补送、手工仅平台查看

转换：每次结果/晚更新 → 同对象准确关联 → 接口回传或手工查看、重复不新增呼叫；回传失败记录并补送，不改变业务结果

## 9. 假设与约束

- P1仅分析排序，不是实施先后
- 北京时间原导入自然日priority衰减保留；真实状态/存量修改能力与每日时刻交开发核实
- DCC管理重导与计数，平台不建预算/计时器；供应商内部尝试完整性及SIP晚更新交开发核实
- 工作时间边界（SRC-078/079）：平台按DCC传入priority保存、同任务排序并提交，不新增工作时间策略、不因工作时间到来自动提权；既有自然日衰减最低1、同级FIFO与已提交不撤回保持。低优先级不是禁止呼叫；无新增功能。
