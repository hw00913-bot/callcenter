## 二、严重问题（P0）— 演示会真实触发

### P0-1 · 只填日期点"查询"，整张表格被清空

**位置**：`js/common.js:69-108`（`doQuery`）

收集筛选条件时，日期区间和多选文本都进了 `conditions`：

```js
// common.js:70-77 —— conditions 收集了 3 类条件
if (dateInputs.length === 2 && dateInputs[0].value && dateInputs[1].value) {
  conditions.push(`时间: ...`);
}
scope.querySelectorAll('.filter-select').forEach(sel => { if (sel.value) conditions.push(sel.value); });
scope.querySelectorAll('.multi-select-display').forEach(disp => { ... conditions.push(text); });
```

但真正做行匹配时，**只认 `.filter-select`**：

```js
// common.js:99-101
scope.querySelectorAll('.filter-select').forEach(sel => {
  if (sel.value && text.includes(sel.value.toLowerCase())) match = true;
});
```

**后果**：只要用户只填了日期区间（没选下拉），`conditions.length > 0` → `hasFilters = true` → 但没有任何 `sel.value` 命中 → 所有行 `display:'none'`，页面显示"共 0 条数据"。表格凭空消失。

**为什么必踩**：这是列表页最常规的操作路径——演示者填个时间范围点查询，是最自然的动作。

附带：`common.js:102` 的 `if (match || conditions.length === 0)` 中后半段是死代码（`hasFilters=false` 时前 6 行已 `return`）。

### P0-2 · 坐席工作台有一个永不停止的 1 秒定时器

**位置**：`js/pages/agent-workbench.js:911`

```js
setInterval(() => {
  if(['offered','answering'].includes(phase)&&call?.offerExpiresAt<=Date.now())return finishReceiving('坐席未接听');
  if (phase !== 'connected' || !call) return;
  call.durationSeconds = ...;
  document.querySelectorAll('[data-seat-timer]').forEach(...);
  persist();          // ← 每秒写一次 sessionStorage
}, 1000);
```

**问题**：这个定时器在文件顶层直接启动，**全项目找不到对应的 `clearInterval`**。另外两个页面（`operations-monitor.js:11/15`、`scenario-demo.js:371/374/376`）都写了自清理逻辑，唯独这里没有。

**后果**：页面切走后定时器仍在后台每秒运行，持续 `querySelectorAll` + `persist()` 写 sessionStorage。长时间演示会累积 CPU 与 IO 开销，并可能把已经失效的通话状态写回存储。

### P0-3 · 编辑任务时若任务被删除，弹层直接崩溃

**位置**：`js/pages/cloud-task-workspace.js:1017` 触发，`:954` 崩溃

```js
// :1017  refreshPreview()
host.innerHTML = d.editTaskId ? editPreview(d, taskById(d.editTaskId)) : preview(d);

// :954    editPreview() 无条件解引用 row
<h3>${esc(draft.values.name || row.name)}</h3>
<p>${esc(tenant(row.tenantId).name || '所属组织')}</p>
```

`taskById()` 在任务被删除或当前租户无权访问时返回 `null`，`editPreview` 未做任何判空 → `TypeError`。

**后果**：`refreshPreview()` 抛错后，向导后续的 `update()` 全部中断，弹层卡死在半渲染状态。多标签演示（一个标签删任务、一个标签编辑）时最容易触发。

### P0-4 · `crypto.randomUUID()` 在非安全上下文直接抛错，登录中断

**位置**：`js/app.js:702`（登录主流程）+ 另有 8 处无守卫调用

```js
state.sessionId = crypto.randomUUID();   // app.js:702
```

无守卫的调用点：`alicti-seat-import.js:131,133`、`alicti-number-import.js:89,90`、`repeat-predictive.js:112,113`、`alicti-accounts.js:200,206`、`account-seat.js:134`。

**矛盾点**：`dcc-runtime.js:71` 明明已经写了正确写法——

```js
const uniqueDemoId = () => typeof window.crypto?.randomUUID === 'function'
  ? window.crypto.randomUUID() : Date.now().toString(36) + '-' + (++applicationSequence);
```

说明团队知道这个风险，但只在 1 处做了防护，其余 8 处裸奔。

**触发条件**：`crypto.randomUUID` 仅在安全上下文（HTTPS 或 localhost）可用。用 `启动原型.command` 起 localhost 没问题；但**一旦通过局域网 IP（如 `http://192.168.x.x`）在别的机器上演示，登录直接 TypeError**。

## 四、架构与可维护性（P2，但最值得关注）

### 根本风险：112 个 `<script>` 同步加载 + 隐式顺序依赖

`index.html` 里 112 个 JS、38 个 CSS 全部以普通 `<script>` / `<link>` 顺序加载，**无 `defer`、无 `async`、无打包、无模块系统**，文件间靠全局变量互相调用。

具体表现：

- **每个文件都阻塞首屏**，38 个 CSS 请求 + 112 个 JS 请求串行解析
- **加载顺序是隐式契约**：`nav.js:346` 在顶层调用 `AppState.subscribe`、`app.js:12` 顶层读 `window.CloudCallData`，这些都依赖"某个文件必须先加载"。顺序一旦调整（比如为了缓存加了版本号、或调整 script 位置）就会 `ReferenceError`
- **TDZ 隐患**：`nav.js:100` 的 `renderNav` 引用了第 153 行才声明的 `const secondaryFrames`。当前调用点都是异步的所以不报错，但只要把 `AppState.subscribe` 上移一行就崩
- **全局命名空间**：`common.js` 未包 IIFE，19 个顶层函数（`switchTab`/`doQuery`/`doRefresh`…）直接挂 window。目前**未发现真实重名覆盖**（已扫描确认 `window.Pages` 的 18 处都是幂等的 `|| {}` 写法），但名字过于通用，后续新增文件撞名是迟早的事

### 单文件膨胀

`cloud-task-workspace.js` 2,252 行，单个 IIFE 内平铺约 90 个函数，无分层：持久化（1-250）、向导渲染（600-1000）、校验（1300-1420）、提交/回收（1420-1720）、任务中心（1800-2250）混在一起。

明确的重复：

- `persist(); AppState.setDirty(true); clearFormErrors(); refresh(true); refreshPreview();` 这个五连序列出现 **8 次**（766、1171、1192、1198、1205、1222、1228、1252）
- 卡片渲染器写了两份：`confirmStep` 的 `card()`（:926）与 `centerResources` 的 `card()`（:1994），933-935 与 1997-1999 是同一组三张卡片的复制粘贴
- 表单控件生成器有 **4 套互不相通**的实现：`taskNumberField`(:785)、`resourceStep` 内 `select` 闭包(:807)、`timeConditionChoices`(:292)、`callerFields`(:340)

### 其他

- `nav.js:167` `while(route?.redirect)` 无环检测（配置写错即死循环）
- `nav.js:156` `layerSelector` 缺 `.modal-overlay`（`common.js:369` 有）→ 路由切换时这类旧弹窗不被清理
- `platform-ui.js:252` `layerOrder` 只增不减
- `app.js:855` `DOMContentLoaded` 未加 `{once:true}`
- `app.js:198 esc()` 与 `platform-ui.js:12 escape()` 功能重复；`maskPhone`/`formatDuration` 在 common.js 与业务文件各一份

## 五、做得好的地方

值得肯定，不要动：

1. **零调试残留** —— 113 个文件里 `console.log`/`debugger`/`TODO` 全部为 0，这在原型项目里很罕见
2. **转义纪律好** —— 104 处 `innerHTML` 中绝大多数走 `PlatformUI.escape` 或各文件 `esc` 别名；`ui.table`/`ui.alert` 内部已转义。已验证的高危输入路径（CSV 导入表头、名单预览、头像上传）全部安全。全项目 `javascript:` 注入点 **0 处**
3. **存储层设计扎实** —— `alicti-storage.js` 用前缀隔离 + JSON 字典压缩，避免污染宿主 localStorage；compact/unpack 全程 try/catch 且失败时保留原值，不影响数据
4. **并发保护严谨** —— `customer-business.js` 的 revision 乐观锁、`customer-directory.js` 的 `syncing` 重入保护与 `unmerged` 冲突隔离，都是正经工程写法
5. **登录态处理正确** —— 只存 ID 不存凭据，用 sessionStorage，logout 显式 removeItem
6. **资源引用零缺失** —— 112 个 JS + 38 个 CSS 引用全部命中，没有断链
