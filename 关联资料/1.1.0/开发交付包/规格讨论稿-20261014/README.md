## 本轮最高优先级（P0）

三项并列最高优先级，先安排方案确认、开发与验收。按依赖推进，不把P0理解为已实现或门禁豁免。

| 优先级 | 范围 | 必须交付的行为 |
| --- | --- | --- |
| P0 | 应用接入 | 应用列表、新增、详情、修改、删除，应用与租户多对多关联、密钥与指定租户身份获取、每个应用回调地址保存。 |
| P0 | 导入客户接口 | DCC、天网等应用接口导入共用能力；明确外呼方式。预外呼必传原供应商任务ID taskId并核归属，按任务坐席组；人工外呼agentWorkNo选填；有效值分配该坐席，缺省保持未分配，业务跟进初始未同步。校验回调配置、逐行结果、请求去重及身份隔离。 新API导入请求必带业务批次号，同app/tenant可多次导入复用；与requestId去重、平台主子批和供应商fileId分离。 六个选填客户资料字段逐行保存，不删除leadCode/phone/priority，业务接口展开字段清单。 请求级businessType必填且按验真租户启用码校验，逐条保存，幂等含类型。 |
| P0 | 外呼未接通填单 | 人工拨号后、预外呼坐席振铃时即可填写原跟进表单；未接通结束保留内容并选择通话状态保存。号码状态沿API-327完整20描述/16编码，712拒接；人工状态与线路结果分别保存。 通话结束且处理结果为已完成沟通并可靠保存后，将本次通话和本次已保存业务信息快照回调原业务系统，携原业务批次号。 已填选填业务字段及选项的业务编码一并快照回传，不只传显示名称。 原导入意向门店/车系编码与名称、Smartcode及留资时间在现有表单和详情显示，完成快照携本次来源原值。 适用每次结果/进度及完成沟通回调携原业务类型码。 |

**实施顺序**

1. 应用接入与租户身份/回调配置先提供接口导入前提；同一P0内可并行开发工作台填单。
2. 分别验收预外呼taskId路由和人工agentWorkNo分配，再串联已约定的结果回调。
3. 联验未接通选择状态、保存/恢复与继续跟进依赖；正式实施和上线前仍按原证据要求核验。
4. 按原app/tenant/record/call固化完成沟通快照，再独立交付与确认；验证批次可复用、重传不重复、保存失败不发、跨应用不串及晚到话单版本方案。

其他v1.1.0功能保留原范围和原优先级；本轮不删除、延期或统一改为P1。混合功能/验收仅指定的接口或填单部分升P0。

## 本轮接口分配与状态修订 · 2026-10-16

人工外呼agentWorkNo选填；缺省接收且不分配云呼叫坐席、不进入个人待联系；显式提供时精确校验当前租户唯一有效坐席，错误拒绝该行，不回退成未分配或改派。预外呼仍必须传准确taskId并沿任务坐席组，工号不覆盖组分配。

所有新接口来源的业务跟进初始为“未同步”，与是否已分配、是否拨打/接通分开。无工号不认定未联系；有有效工号表示已分配云呼叫坐席，不凭分配就认定业务待联系。平台本人保存的明确处理结果或经过准确关联的外部业务处理结果方可更新跟进；仅AliCti话单、挂断、接通和时长不能推断业务已完成。平台明确继续跟进/需要再次联系保留当前有权坐席待办；结束性处理结果已保存可标跟进已完成，但独立“完成沟通回调”仍只由精确结果已完成沟通触发。

在既有“导入与分配”批次清单只读展示人工和预外呼接口导入；按当前权限保留原app/tenant/request与原客户记录、预测task和实际映射。相同businessBatchNo可多请求复用但不合并不同请求；不复制/迁移原账本，不重新分配或重复导入。预外呼显示任务去向，人工无工号显示未分配云呼叫坐席。

DCC拨号入口与平台共用同一AliCti；线索负责人/平台分配坐席与本通实际坐席分别保存展示。外部人工通话按稳定app、已鉴权tenant、供应商实例、原记录与callId精确关联；实际坐席取该通真实话单工号，不反写线索分配。不能仅按手机号、同名业务批次或工号关联，错误/歧义/冲突保持待核。外部通话的业务结果为独立显式同步，不能用话单接通代替。

仅影响本次新导入及本轮显式合成验证；历史记录状态和原账本不批量改写，旧无值保留未知。旧SRC125的S1/S2通过仅证明当时104条正文，未继承为SRC126通过；正式104条验收/US规范化及S1开始的下游复核待后续正式执行，G1/G2/G3仍pending。

本地合成同步使用同原记录的独立call版本/业务版本。平台保存跟进时记录已观察到的外部业务版本，旧版本不覆盖本次平台保存，只有更高外部业务版本可更新显示，不比较两套系统时钟。任一准确关联的通话未结束均保留在途占用；外部资料不可读或关联待核时阻止新拨打和重新分配。真实双方版本冲突协议仍待评审。

有有效云呼叫分配的接口人工客户，跟进未同步时由有权本人显式确认平台联系安排后才进入个人待联系；该安排不表示DCC尚未联系。人工接口补分配只选坐席，不静默改成预外呼任务，原导入方式与原应用回调归属保留。

本轮局部证据：[接口分配与状态核验](../../prototype/memory/verification-evidence/import-assignment-status-20261016.json)。旧104条验收原文继续保存；受影响条款见验收页的本轮适用边界，不能据旧expected将工号仍当必填。

## 本版约定

- 客户档案已接入新版预外呼任务的API及手工导入；同企业、同租户、同归一号码归一档案，按当前权限查看各原导入与联系记录。归集只读，不复制或合并原账本，不用同号最新资料覆盖原业务记录或通话，不改变原回调归属及计次。真实后端归集仍待工程实现。
- 导入接口请求级必填businessType（业务类型编码），一次一种，取已验真租户当前启用类型；缺失/无效/停用的新请求拒收。逐条保存原码，名单/详情展示原名称并保编码，坐席按原类型表单跟进，回调携原码。同requestId改类型冲突，已受理同内容技术重放不新增，后续停用不改历史；不同类型分次请求可复用businessBatchNo。原手工CSV不增加逐行必填。
- 应用回调地址已补到新增／修改和详情，列表显示配置状态；本地保存与缺地址导入阻断已局部验证，真实回调仍待实现。
- 每条线索新增选填的意向门店编码、意向门店名称、意向车系编码、意向车系、Smartcode及留资时间；原值显示在既有预览、客户/通话详情和早填单。留资时间来自业务方，不默认平台导入时间。
- 新接口导入请求带业务批次号（建议字段businessBatchNo），同应用/租户可复用；每条记录保存原值并在每次回调带回，requestId继续单独防重。该字段不增加到原手工CSV必填列。
- 通话结束且处理结果为“已完成沟通”并保存成功后，新增完成沟通回调：包含本次通话记录、本次保存的客户业务信息和原业务批次号。已填选填字段及其选项的业务编码也必须回传，多选保留所有选中编码。每次结果/进度回调仍保留；回调失败只补送，不重新拨号。
- 应用与租户多对多，业务系统分别配置应用凭据及回调地址。建议取身份时显式指定租户、校验关联并绑定token；正式报文待审。
- 导入指定预外呼或人工外呼。预外呼仍按任务坐席组分配；人工外呼工号选填；缺省接收、不分配、不进入个人待办，有有效值才分配，显式无效拒绝该行。业务跟进初始未同步，不套用预测任务和批次。
- 所有接入应用都回调原业务系统，未配置回调地址先拒绝导入。无应用来源的手工界面导入保持平台内处理。
- 人工拨号后、预外呼坐席振铃时可填跟进草稿，原型已局部验证；未接通通话状态选择、条件必填与独立保存现已局部核验，712为拒接，同码不同描述分别保留；人工记录不覆盖客观通话结果。
- 继续跟进在成功保存后保留待联系。预外呼转由当前坐席后续人工跟进；供应商自动重呼排他尚待验证，不能仅凭待联系列表就声称可以安全再次拨号。
- 预测范围继续沿用三类失败确认后120秒自动补提交、八类人工补提交，共享首次之外2次；未知不盲发，秒挂不重呼。
