# 阿里团队补充接口与当前项目契合度评估

评估日期：2026-09-14。评估对象为供应商补充 Excel 与当前交付版本 `2026-09-14-cf02-scope-1`。本次仅形成评估，未修改原型、开发契约、待确认状态或供应商原始文件。

**结论：补充材料足以推进已有坐席同步、技能队列配置、未启动任务删除等功能的实现，但不能据此认定当前项目已完整满足。号码开通与企业账号绑定仍需供应商运营流程；共享号码按键分租户、无坐席兜底与结果归属仍缺完整契约。部分补充参数还与官方文档或当前需求存在冲突。**

## 必须纠正或统一的关键内容

1. **号码路径与控制范围。** 官方是 [`enterpriseHotline/batchUpdateNumber`](https://wiki.alicti.cn/html/wiki/API/配置管理/企业管理/更新号码外显属性.html)，并非表中的 `batchUpdate`。`numberList` 最多 1000 个；用途/状态字段列为可选，不能从本页推出“所有字段必须全量提交”。`isIbRight` 是呼入转坐席侧外显权限，`isInUse` 是预览外呼客户侧外显权限，均不能直接等同于停用整条呼入线路。该接口另外提供 `status=0/1`，但未说明对呼入和在途的完整影响。
2. **坐席批量创建格式。** [`agent/batchCreate`](https://wiki.alicti.cn/html/wiki/API/座席数据管理/座席批量新增.html) 必填起始工号 `cno`、结束工号 `endCno`，一次最多 100 个，并非任意坐席行数组。任意工号和不同姓名的坐席清单需由平台逐项编排或按接口适用范围分组，不应把整份名单原样传入。接口还区分创建失败与“创建成功但技能绑定失败”。
3. **在线修改限制。** [`agent/update`](https://wiki.alicti.cn/html/wiki/API/座席数据管理/座席更新.html) 和 [`agent/batchUpdateAgentSkill`](https://wiki.alicti.cn/html/wiki/API/座席数据管理/批量更新座席技能列表.html) 都列出 20023 在线错误。需要明确允许在线修改的字段和例外条件，不能仅由“文档没禁止”推出允许。
4. **暂停单位。** [`task/pause`](https://wiki.alicti.cn/html/wiki/API/预测式外呼/任务暂停接口.html) 的请求没有写单位，[`TaskProperty.pauseDuration`](https://wiki.alicti.cn/html/wiki/API/dataType/TaskProperty.html) 明确写分钟，Excel 写秒。应取得同一次请求和状态查询的例子，明确请求单位、返回单位和是否转换，避免 60 倍偏差。0 的含义可记录为供应商新增说明，与单位问题分开。
5. **技能等级。** 补充表 `缺口总览!I20`、`需补充接口清单!F27` 写 1–10；当前原型是已接受的本地 1–999。两者不能同时成为可提交的范围。实施前应统一此规则，避免把 [`queue.weight`](https://wiki.alicti.cn/html/wiki/API/配置管理/队列管理/更新队列.html) 的“1–10、越大越优先”误当成 `skillLevels` 的“越小越优先”。本次评估不擅自覆盖原型的已接受约束。
6. **呼入兜底与多租户。** Excel `缺口总览!I17` 用外呼设置回复呼入兜底，而明细改为队列和路由。应按 [`queue/update`](https://wiki.alicti.cn/html/wiki/API/配置管理/队列管理/更新队列.html)、[`ivrRouter/create`](https://wiki.alicti.cn/html/wiki/API/配置管理/呼入路由管理/新增呼入路由设置接口.html) 与具体 IVR 节点契约逐项映射。路由的 `active` 为 1 启用、2 停用，时间和中继条件多个值用分号；这些字段不能照搬其他接口的 0/1 或逗号规则。缺少具体“无可用坐席→转指定分支→回传归属”例子时，不能把兜底和分店归属标为已完成。
7. **ASR 说话方并未解决。** [`asr/get`](https://wiki.alicti.cn/html/wiki/API/ASR语音转写/ASR数据获取接口.html) 的 `all=true` 示例实际含 `side=out/in`；补充表尾“不是 side 枚举”的表述不完整。尚未给出各呼叫类型的角色映射，更未回答 `isAsr` 与 `cdrIsAsr` 的优先级。文本定位录音已取消，不需要继续追问时间对齐。

## 对实施安排的建议

- 可优先推进：已有坐席同步和失败查证、技能/队列基础配置、任务查询监控、受限的未启动任务删除。恢复入口可依据供应商补充设计，但暂停单位不能猜测。
- 号码资源采用“供应商申请开通/归属处理→接口同步→平台租户授权”的方案可以支持使用已开通资源的主流程；这与“本平台全自动开通绑定号码”是不同交付范围，后者本批资料不满足。
- 呼入基础路由可以接入，按键分店与兜底需用一个完整样例确认：同一个账号 7522240、同一个号码、至少两个门店、正常时段与非服务时段、无可用坐席，并给出每条结果如何回到唯一门店的字段。
- 正式给开发 agent 的输入应补齐本轮核实的真实路径、字段结构、枚举及错误码，保留供应商 Excel 单元格来源；纠正后的契约与验收用例同步后，再解除对应功能的待确认限制。不能将这份补充表逐字当成可执行接口契约。
